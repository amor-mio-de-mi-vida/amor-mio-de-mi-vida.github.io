0.2 设计题的通用解题框架

设计题和普通算法题的区别在于：没有「一个输入一个输出」，而是一组操作共享同一份状态，每个操作都有复杂度要求。按下面四步走，基本不会卡住。

  1. 列操作表，标出复杂度目标。 把每个接口写下来，旁边写上题目要求或你打算做到的复杂度。这一步同时是和面试官确认需求的过程：key 会不会重复、时间戳是否递增、容量上限多大、非法输入怎么处理。
  2. 为每个操作找「最便宜的结构」，再看它们能不能共存。 单一结构通常满足不了所有操作，答案几乎总是两个结构的组合：一个负责按 key 定位（哈希表），另一个负责维护某种顺序（链表、堆、有序集合、数组）。见 0.3 的速查表。
  3. 写下不变量。 两个结构之间必须始终保持的关系，例如「哈希表里的每个 key 在链表里恰好有一个节点」「lo_ 的每个数不大于 hi_ 的每个数，且两者大小差不超过 1」。每个操作结束时都要恢复不变量。bug 几乎都出在某条路径忘了同步另一个结构。
  4. 逐个操作过边界。 空结构、容量为 1、重复插入同一个 key、删除不存在的 key、被操作的恰好是头 / 尾 / 最后一个元素。

能主动说出第 3 步的候选人很少，这是拉开差距的地方：面试官追问「如果再加一个操作 X 呢」时，你只需要检查 X 会不会破坏不变量，而不是重新想一遍。

2.1 最小栈（155）

不变量：第 i 层存的第二个值 = 栈底到第 i 层所有元素的最小值。栈只在顶端变化，所以弹出一层后，下面各层记录的最小值依然有效。

class MinStack {
    vector<pair<int, int>> st_;                    // {值, 压入该值之后的栈内最小值}
public:
    void push(int val) {
        int curMin = st_.empty() ? val : min(val, st_.back().second);
        st_.push_back({val, curMin});
    }
    void pop() { st_.pop_back(); }
    int top() { return st_.back().first; }
    int getMin() { return st_.back().second; }
};

Q1 · 最小栈为什么要每层都存一份最小值

4 条追问与解答
  • 只用一个变量记最小值为什么不行？ 弹出最小值之后需要知道「次小值」，而次小值取决于栈里还剩哪些元素，一个变量存不下这段历史。每层存一份相当于给历史拍快照，LIFO 保证弹出一层后下一层的快照仍然正确。
  • 辅助栈能不能只在遇到更小值时才压？ 能，可以省空间，但判断必须用 <= 而不是 <。原因是重复的最小值要各压一次，否则弹出其中一个时辅助栈跟着弹，剩下那个相同的最小值就丢了。
  • O(1) 额外空间怎么做？ 栈里不存原值，存 val - curMin 的差值。压入时差值为负说明它成了新的最小值；弹出时如果差值为负，上一个最小值 = curMin - diff。原因是差值同时编码了「原值」和「最小值是否在这一步发生变化」两条信息。差值可能溢出 int，要用 long long。
  • 最大栈（716）多了 popMax 为什么就变成难题？ popMax 删的是栈中间的元素，破坏了「只在一端变化」这个前提，下面各层的快照全部失效。所以要换成双向链表（O(1) 删中间）+ 有序映射（O(log n) 找最大值对应的节点）。

2.2 双栈实现队列（232）

不变量：out_ 从栈顶到栈底是队列里最老的那批元素（按出队顺序），in_ 从栈底到栈顶是较新的那批。整个队列的顺序 = out_ 自顶向下，接 in_ 自底向上。

class MyQueue {
    stack<int> in_, out_;
    void shift() {                                 // 只有 out_ 空了才搬，否则会打乱先后顺序
        if (!out_.empty()) return;
        while (!in_.empty()) { out_.push(in_.top()); in_.pop(); }
    }
public:
    void push(int x) { in_.push(x); }
    int pop() { shift(); int v = out_.top(); out_.pop(); return v; }
    int peek() { shift(); return out_.top(); }
    bool empty() { return in_.empty() && out_.empty(); }
};

Q2 · 双栈队列的摊还复杂度怎么证明

3 条追问与解答
  • 为什么是摊还 O(1)？ 每个元素一生最多经历 4 次栈操作：进 in_、出 in_、进 out_、出 out_。n 次队列操作总共最多 4n 次栈操作，平均每次 O(1)。单次 pop 最坏仍是 O(n)，摊还说的是总量而不是单次。
  • 为什么必须等 out_ 空了才搬？ out_ 的栈顶是当前最老的元素。如果它非空时就把 in_ 的元素压上去，新元素会盖在老元素上面，下次出队的就变成了新元素，先进先出被破坏。
  • 反过来用队列实现栈（225）为什么做不到摊还 O(1)？ 栈倒一次顺序反转，倒两次恢复正序，所以两个栈能拼出队列。而队列是先进先出，元素出队再入队只是轮转，相对顺序永远不变；想让最新的元素排到队头，只能把它前面的 n - 1 个全部轮转一遍，每次 push 都是 O(n)。

2.3 哈希 + 数组：O(1) 插入、删除、随机（380）

不变量：pos_[vals_[i]] == i 对所有 i 成立，且 vals_ 没有空洞（下标连续，才能均匀随机）。

class RandomizedSet {
    vector<int> vals_;
    unordered_map<int, int> pos_;                  // val -> 它在 vals_ 里的下标
public:
    bool insert(int val) {
        if (pos_.count(val)) return false;
        pos_[val] = vals_.size();
        vals_.push_back(val);
        return true;
    }
    bool remove(int val) {
        if (!pos_.count(val)) return false;
        int i = pos_[val], last = vals_.back();
        vals_[i] = last;                           // 用末尾元素填坑，避免 O(n) 搬移
        pos_[last] = i;                            // 先改 last 的下标，再删 val：val == last 时顺序反了会出错
        pos_.erase(val);
        vals_.pop_back();
        return true;
    }
    int getRandom() { return vals_[rand() % vals_.size()]; }
};

Q3 · 为什么 O(1) 随机必须是哈希加数组

4 条追问与解答
  • 只用哈希表为什么不行？ 均匀随机需要「O(1) 取第 k 个元素」，这要求元素放在连续下标上。哈希表的元素散落在桶里，取第 k 个只能遍历，O(n)；随机挑一个桶再挑桶内元素又不均匀，因为各桶长度不同。
  • 为什么删除时和末尾交换？ 数组删中间之所以 O(n)，是因为要保持元素的相对顺序而搬移后面所有元素。这里顺序没有意义，只要求下标连续，所以拿末尾元素填坑、再 pop_back，O(1)。
  • 允许重复（381）要改哪里？ pos_ 的 value 从单个下标换成下标集合 unordered_set<int>。删除时从 val 的集合里任取一个下标 i，安全的更新顺序是：val 的集合删 i → last 的集合加 i → last 的集合删 n - 1。原因是当 val 就是 last 时两个集合是同一个，这个顺序在 i 等于或不等于 n - 1 两种情况下都正确，换个顺序就会在其中一种情况下多删或漏删。
  • getRandom 要按出现次数加权怎么办？ 381 天然就是加权的：重复元素在数组里占了多个槽位，被抽中的概率正比于出现次数，不需要额外处理。

2.4 对顶堆：数据流中位数（295）

不变量：lo_ 的每个数 ≤ hi_ 的每个数；lo_.size() 等于 hi_.size() 或比它多 1。于是中位数只和两个堆顶有关。

class MedianFinder {
    priority_queue<int> lo_;                                  // 大顶堆：较小的一半
    priority_queue<int, vector<int>, greater<int>> hi_;       // 小顶堆：较大的一半
public:
    void addNum(int num) {
        lo_.push(num);
        hi_.push(lo_.top()); lo_.pop();            // 新数先过一遍 lo_，保证 lo_ 的每个数 <= hi_ 的每个数
        if (hi_.size() > lo_.size()) { lo_.push(hi_.top()); hi_.pop(); }   // 约定 lo_ 多一个或相等
    }
    double findMedian() {
        if (lo_.size() > hi_.size()) return lo_.top();
        return (lo_.top() + hi_.top()) / 2.0;
    }
};

Q4 · 对顶堆为什么能 O(1) 取中位数

4 条追问与解答
  • 为什么新数要先进 lo_，再把 lo_ 的堆顶转给 hi_？ 为了不写分支就能维持「lo_ 全部 ≤ hi_ 全部」。新数无论大小先进 lo_，此时 lo_ 的堆顶是 lo_ 加上新数之后的最大值，把它交给 hi_ 一定不破坏大小关系；最后只需要按数量调平。如果直接比较新数和堆顶再决定进哪个堆，也对，但要处理堆为空的分支。
  • 为什么不用排序数组加二分插入？ 二分找位置是 O(log n)，但插入要搬移元素，O(n)。中位数只关心分界线两侧的极值，不需要全体有序，堆恰好只维护极值，所以 add 是 O(log n)，find 是 O(1)。
  • 所有数都在 [0, 100] 怎么优化？ 用 101 个计数桶加总数，找中位数时扫一遍桶，O(101) 即 O(1)，空间也是 O(1)。如果是 99% 的数在这个范围：再加两个计数器记小于 0 和大于 100 的个数，只要离群值不到一半，中位数一定落在桶里。
  • 滑动窗口中位数（480）为什么对顶堆就不够了？ 窗口滑动要删除任意一个旧元素，而堆只能删堆顶。两条路：换成两个 multiset（支持任意删除），或者堆 + 懒删除并额外维护两边的「有效元素个数」，因为残留的过期项会让 size() 失真。

2.5 Trie（208）

不变量：从根到某节点的路径唯一对应一个前缀；isEnd 为真当且仅当这个前缀本身是一个被插入过的完整单词。

class Trie {
    struct Node {
        Node* next[26] = {};                       // 全部初始化为 nullptr
        bool isEnd = false;
    };
    Node* root_ = new Node();

    Node* walk(const string& s) {                  // 沿着 s 往下走，走不通返回 nullptr
        Node* cur = root_;
        for (char c : s) {
            cur = cur->next[c - 'a'];
            if (!cur) return nullptr;
        }
        return cur;
    }
public:
    void insert(string word) {
        Node* cur = root_;
        for (char c : word) {
            if (!cur->next[c - 'a']) cur->next[c - 'a'] = new Node();
            cur = cur->next[c - 'a'];
        }
        cur->isEnd = true;
    }
    bool search(string word) { Node* n = walk(word); return n && n->isEnd; }
    bool startsWith(string prefix) { return walk(prefix) != nullptr; }
};

Q5 · Trie 的实现取舍

4 条追问与解答
  • 面试版用 new 建节点、没写析构，会被追问吗？工程上怎么写？ 面试里时间有限，默认可以不写析构，但要主动说一句「这里省略了释放」。工程上常见的做法是节点池：所有节点放进一个 vector<Node>，孩子存 int 下标而不是指针。好处有三个：vector 析构时整体释放，不用写递归 delete（很深的 Trie 递归析构可能爆栈）；节点连续存放，缓存命中率高；int 下标 4 字节，比 8 字节指针省一半。代价是 vector 扩容会让指向节点的引用失效，所以每次都要通过下标重新取。
  • 空间复杂度是多少，字符集很大怎么办？ 最坏 O(总字符数 × 字符集大小)，每个节点都开满 26 个槽位。字符集大（如 Unicode）时把数组换成哈希表或有序映射，用时间换空间；进一步压缩是 radix tree，把只有一个孩子的链压成一个节点，节点上存字符串片段。
  • Trie 和哈希表存字典怎么选？ 精确查找两者都是 O(L)，哈希表常数更小。Trie 的优势只在三件事：前缀查询、按字典序遍历、多模式匹配（AC 自动机的底座）。原因是哈希函数把整个字符串打散了，前缀相同的串之间没有任何位置关系，而 Trie 把公共前缀显式地存成公共路径。需求里没有「前缀」就用哈希表。
  • 怎么支持删除？ 每个节点加一个「经过次数」（1804 题的做法），删除时沿路径逐个减一。原因是一个节点可能被多个单词共享，只有计数归零才说明没有单词再经过它，才能回收。

2.6 堆 + 懒删除（3408，同构题 2353 / 2034 / 2349 / 3885）

不变量：哈希表 info_ 是唯一的真相；堆里的项只是「曾经的快照」，一个堆项有效当且仅当它和 info_ 里的当前值完全一致。

class TaskManager {
    unordered_map<int, pair<int, int>> info_;      // taskId -> {priority, userId}，这是唯一的真相
    priority_queue<pair<int, int>> heap_;          // {priority, taskId}，允许残留过期项
public:
    TaskManager(vector<vector<int>>& tasks) {
        for (auto& t : tasks) add(t[0], t[1], t[2]);
    }
    void add(int userId, int taskId, int priority) {
        info_[taskId] = {priority, userId};
        heap_.push({priority, taskId});
    }
    void edit(int taskId, int newPriority) {
        info_[taskId].first = newPriority;
        heap_.push({newPriority, taskId});         // 旧项不删，留到出堆时识别
    }
    void rmv(int taskId) { info_.erase(taskId); }
    int execTop() {
        while (!heap_.empty()) {
            auto [pri, id] = heap_.top();
            heap_.pop();
            if (!info_.count(id) || info_[id].first != pri) continue;   // 和真相对不上，是过期项
            int user = info_[id].second;
            info_.erase(id);
            return user;
        }
        return -1;
    }
};

Q6 · 堆里的元素优先级会变，怎么办

5 条追问与解答
  • 为什么不直接在堆里改优先级？ std::priority_queue 只暴露堆顶，找到任意元素要 O(n)。即使找到了，改完还要上浮或下沉，这需要知道它在底层数组里的下标，也就是要自己维护一张「id → 堆下标」的表并在每次交换时同步更新，这就是索引堆。能写，但代码量和出错概率都远高于懒删除。
  • 懒删除为什么正确？ 每次修改都压入一个新快照，旧快照留在堆里。出堆时和 info_ 比对：id 已不存在，或优先级对不上，就丢弃。同一个 (优先级, id) 可能在堆里有多份（比如改走又改回来），但第一份被执行后 info_ 里的记录已删除，后面几份自然被判为过期。
  • 代价是什么？ 空间从 O(存活元素数) 变成 O(历史操作总数)。时间上单次 execTop 可能连续弹出多个过期项，但每个堆项一生只会被弹出一次，所以摊还仍是 O(log n)。
  • 什么时候不该用懒删除？ 修改极多而出堆极少的场景，过期项只进不出，内存持续上涨。这时换成 set<pair<int,int>>（修改 = 先删旧 pair 再插新 pair，O(log n)），或者在过期项超过一半时重建堆。
  • set 和 priority_queue 性能上怎么选？ 堆的底层是连续数组，没有逐节点内存分配，缓存友好，常数小；set 是红黑树，每个节点单独分配、靠指针跳转，常数大几倍，但支持任意删除和有序遍历。只需要取最值用堆，需要删除或范围查询用 set。

2.7 环形队列（622）

不变量：有效元素是从 head_ 开始、长度为 size_ 的一段，下标对 cap_ 取模；0 ≤ size_ ≤ cap_。

class MyCircularQueue {
    vector<int> buf_;
    int cap_, head_ = 0, size_ = 0;                // 记 head + size，不记 tail：空和满不会混淆
public:
    MyCircularQueue(int k) : buf_(k), cap_(k) {}
    bool enQueue(int value) {
        if (isFull()) return false;
        buf_[(head_ + size_) % cap_] = value;
        ++size_;
        return true;
    }
    bool deQueue() {
        if (isEmpty()) return false;
        head_ = (head_ + 1) % cap_;
        --size_;
        return true;
    }
    int Front() { return isEmpty() ? -1 : buf_[head_]; }
    int Rear() { return isEmpty() ? -1 : buf_[(head_ + size_ - 1) % cap_]; }
    bool isEmpty() { return size_ == 0; }
    bool isFull() { return size_ == cap_; }
};

Q7 · 环形缓冲区怎么区分空和满

3 条追问与解答
  • 为什么记 size 而不是 tail？ 只记 head 和 tail 时，空和满都表现为 head == tail，无法区分。解法有两种：多记一个 size，或者故意浪费一个槽位（满定义为 (tail + 1) % cap == head）。单线程下记 size 最直观。
  • 那「浪费一个槽位」的方案有什么用？ 单生产者单消费者的无锁队列用的就是它。原因是 head 只被消费者写、tail 只被生产者写，两个变量各归一个线程所有，用原子读写就够了；而 size 会被两个线程同时修改，必须用原子的读改写，竞争更重。
  • 容量取 2 的幂有什么好处？ 取模可以换成 & (cap - 1)。整数除法指令的延迟是十几到几十个周期，按位与只要一个周期，环形缓冲区的每次读写都要算下标，热路径上差别明显。双端版本（641）里 head 向前走要写成 (head - 1 + cap) % cap，因为 C++ 对负数取模结果为负；换成按位与之后这个问题也不存在了（无符号下标自然回绕）。

2.8 树状数组（307）

不变量：tree_[i] = 原数组区间 (i - lowbit(i), i] 的和（下标从 1 开始），其中 lowbit(i) = i & -i。

class NumArray {
    vector<int> nums_, tree_;                      // tree_ 下标从 1 开始，tree_[i] 管辖长度为 lowbit(i) 的一段
    int n_;
    void add(int i, int delta) {
        for (; i <= n_; i += i & -i) tree_[i] += delta;
    }
    int prefix(int i) {
        int s = 0;
        for (; i > 0; i -= i & -i) s += tree_[i];
        return s;
    }
public:
    NumArray(vector<int>& nums) : nums_(nums), tree_(nums.size() + 1, 0), n_(nums.size()) {
        for (int i = 0; i < n_; ++i) add(i + 1, nums[i]);
    }
    void update(int index, int val) {
        add(index + 1, val - nums_[index]);        // 树里存的是和，所以传增量而不是新值
        nums_[index] = val;
    }
    int sumRange(int left, int right) { return prefix(right + 1) - prefix(left); }
};

Q8 · 树状数组为什么两个循环方向相反

5 条追问与解答
  • i & -i 为什么是最低位的 1？ 补码下 -i = ~i + 1。取反后最低位的 1 变成 0、它右边的 0 全变成 1；再加 1，进位一路传到那一位把它变回 1、右边变回 0，而左边保持取反状态。所以和原数按位与之后只剩最低位的那个 1。
  • 查询为什么是减 lowbit，更新为什么是加 lowbit？ 查询前缀 [1, i]：tree_[i] 覆盖末尾长度为 lowbit(i) 的一段，去掉这一段后剩下 [1, i - lowbit(i)]，继续同样处理，二进制里有几个 1 就拼几段，最多 log n 段。更新位置 i：要找所有覆盖 i 的节点，i + lowbit(i) 恰好是下一个管辖范围更大、且包含 i 的节点，同样最多 log n 个。
  • 建树能做到 O(n) 吗？ 能。先令 tree_[i] = nums[i - 1]，然后从小到大遍历 i，把 tree_[i] 加到它的直接父节点 tree_[i + lowbit(i)] 上。每个节点只向上贡献一次，所以是 O(n)；模板里逐个 add 的写法是 O(n log n)，面试写这个足够，但要能说出优化。
  • 树状数组和线段树怎么选？ 树状数组代码短、常数小、内存恰好 n；但它靠「区间 = 两个前缀之差」工作，只适用于可以做减法的运算（求和、异或）。区间最值没有逆运算，知道两个前缀的最大值推不出中间一段的最大值，所以必须用线段树。区间赋值、区间加同时区间查询也用线段树 + 懒标记。
  • 要支持「区间加、单点查」怎么办？ 对差分数组建树状数组。区间 [l, r] 加 d 等价于差分数组在 l 处加 d、在 r + 1 处减 d，两次单点更新；某个位置的当前值就是差分数组的前缀和，一次前缀查询。

2.9 时间戳 + 二分（981）

不变量：每个 key 对应的数组按时间戳严格递增。这条不变量不是代码维护的，而是题目「set 的时间戳严格递增」保证的，动手前必须向面试官确认。

class TimeMap {
    // 题目保证同一个 key 的 timestamp 严格递增，所以 vector 追加后天然有序
    unordered_map<string, vector<pair<int, string>>> data_;
public:
    void set(string key, string value, int timestamp) {
        data_[key].push_back({timestamp, value});
    }
    string get(string key, int timestamp) {
        auto& v = data_[key];
        int lo = 0, hi = v.size();                 // 在 [lo, hi) 里找第一个时间戳大于目标的位置
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (v[mid].first <= timestamp) lo = mid + 1;
            else hi = mid;
        }
        return lo == 0 ? "" : v[lo - 1].second;    // 它的前一个就是「不超过目标的最新版本」
    }
};

Q9 · 查「不超过 t 的最新版本」，二分的目标怎么定

4 条追问与解答
  • 为什么二分找的是「第一个大于 t 的位置」再退一格，而不是直接找「最后一个不超过 t 的」？ 两者等价，但前一种写法边界更少：用左闭右开区间，v[mid].first <= t 就往右收、否则 hi = mid，循环结束时 lo 就是第一个大于 t 的位置，它的前一个正好是答案；t 恰好命中某个时间戳时同样成立，只需要处理 lo == 0（前面没有元素）这一种边界。直接找「最后一个不超过」的写法要用闭区间并且 mid 向上取整，否则会死循环，更容易写错。
  • 能直接用标准库的 upper_bound 吗？ 能，但数组元素是 pair，要传自定义比较器，而 upper_bound 的比较器参数顺序是 (目标值, 元素)，lower_bound 是 (元素, 目标值)，两者正好相反，写反了会触发一大段模板报错。面试里手写这六行二分更稳，也顺便展示了二分的基本功。
  • 时间戳不保证递增怎么办？ 追加之后数组不再有序，二分失效。换成 map<int, string>，set 变成 O(log n)，get 用成员函数 upper_bound。这就是为什么动手前要确认输入是否单调：它决定了用数组还是用平衡树。
  • 快照数组（1146）为什么不能每次 snap 拷贝一份？ 拷贝是 O(n) 每次，而两次快照之间通常只改了少数几个位置。每个下标各自挂一个 (snap_id, 值) 的追加数组，只在被修改时记录，空间正比于修改次数；查询时对 snap_id 二分，和本题完全同构。

2.10 跳表（1206）

不变量：每一层都是有序链表；第 i + 1 层的节点集合是第 i 层的子集；第 0 层包含全部元素。

47 行 · 点击折叠
class Skiplist {
    static const int MAX_LEVEL = 16;
    struct Node {
        int val;
        vector<Node*> next;                        // next[i] 是第 i 层的后继
        Node(int v, int level) : val(v), next(level, nullptr) {}
    };
    Node* head_ = new Node(-1, MAX_LEVEL);         // 哨兵头，拥有全部层

    int randomLevel() {
        int level = 1;
        while (level < MAX_LEVEL && rand() % 4 == 0) ++level;   // 每升一层的概率 1/4
        return level;
    }
    // prev[i] = 第 i 层里最后一个 val < target 的节点。始终从最高层找起，省掉维护「当前层数」的代码
    vector<Node*> findPrev(int target) {
        vector<Node*> prev(MAX_LEVEL);
        Node* cur = head_;
        for (int i = MAX_LEVEL - 1; i >= 0; --i) {
            while (cur->next[i] && cur->next[i]->val < target) cur = cur->next[i];
            prev[i] = cur;
        }
        return prev;
    }
public:
    bool search(int target) {
        Node* p = findPrev(target)[0]->next[0];
        return p && p->val == target;
    }
    void add(int num) {
        vector<Node*> prev = findPrev(num);
        int level = randomLevel();
        Node* node = new Node(num, level);
        for (int i = 0; i < level; ++i) {          // 在第 0 到 level - 1 层各做一次链表插入
            node->next[i] = prev[i]->next[i];
            prev[i]->next[i] = node;
        }
    }
    bool erase(int num) {
        vector<Node*> prev = findPrev(num);
        Node* p = prev[0]->next[0];
        if (!p || p->val != num) return false;
        for (int i = 0; i < (int)p->next.size(); ++i) prev[i]->next[i] = p->next[i];
        delete p;
        return true;
    }
};

Q10 · 跳表的复杂度和工程取舍

5 条追问与解答
  • 为什么期望 O(log n)？ 每个节点以概率 p 晋升到上一层，所以第 i 层期望有 n · p^i 个节点，层数期望为 log n（以 1/p 为底）。查找时在每一层向右走的期望步数不超过 1/p（再多走一步就说明那个节点本应出现在上一层），总步数 = 层数 × 每层常数。
  • p 取 1/2 还是 1/4？ p 越小，层数越少，每个节点的平均指针数 1 / (1 - p) 也越少：p = 1/2 时 2 个，p = 1/4 时约 1.33 个；代价是每层横向多走几步。Redis 取 1/4，原因是查找步数相差不大，但每个节点的指针数少了三分之一。
  • 有重复值时，erase 直接改 prev[i]->next[i] 会不会删错节点？ 不会。findPrev 找的是每层最后一个小于 num 的节点，所以 prev[i]->next[i] 是第 i 层第一个不小于 num 的节点，而 p 是第 0 层第一个等于 num 的节点。各层的相对顺序一致：如果第 i 层有另一个等值节点排在 p 前面，它在第 0 层也必然排在 p 前面，与 p 是第一个矛盾。所以在 p 出现的每一层，prev[i] 的后继恰好就是 p，不需要再判断。
  • Redis 的有序集合为什么用跳表而不是红黑树？ 作者给的理由有三条：范围查询是主要操作，跳表找到起点后沿底层链表顺序走即可，红黑树要做中序后继；实现和调试简单得多；内存占用可以用 p 调节，并不比平衡树差。
  • 为什么说跳表对并发更友好？ 插入只修改新节点每层前驱的那几个指针，影响是局部的；红黑树的旋转和重新着色会沿着路径向上传播，可能牵动远处的节点，要锁的范围大。所以无锁有序结构基本都是跳表，例如 Java 的 ConcurrentSkipListMap 和 LevelDB 的 memtable（单写多读，读不加锁）。
