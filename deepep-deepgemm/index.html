DeepEP 与 DeepGEMM 精读

DeepEP 是 DeepSeek 开源的专家并行通信库，DeepGEMM 是配套的 FP8/FP4/BF16 矩阵乘内核库。两者合起来，覆盖一层 MoE 从搬数据到做计算的完整路径。这个系列对着源码逐篇拆解它们的核心设计。

导读与背景

  1. 导读
    DeepEP 与 DeepGEMM 精读：系列导读

    两个库各管什么，17 篇精读怎样分成两卷；两卷在三处交汇：masked GEMM 接 dispatch 的输出，Mega MoE 把通信搬进内核，DeepJIT 被两个仓库共用。

    入口约 6 分钟
  2. 背景第 1 篇bg01
    MoE 与专家并行：为什么要搬数据

    MoE 把稠密 FFN 拆成几百个专家，每个 token 只激活其中 k 个。专家分散到多块 GPU 之后，就多出 dispatch 和 combine 两次全对全通信。

    入口约 7 分钟
  3. 背景第 2 篇bg02
    GPU 硬件速查：SM、TMA、张量核与 NVLink

    线程层级与内存层级，Hopper 的 TMA、WGMMA、mbarrier，Blackwell 的 TMEM 与 tcgen05，GEMM 为什么要分块，NVLink 与 RDMA 差在哪。文末有术语速查表。

    入口约 8 分钟先读：bg01

DeepEP 卷：通信

DeepEP 是一个 Python + CUDA 通信库，对外提供四个缓冲区类：EPBuffer（dispatch / combine，ep01–ep06）、BucketBuffer（all-gather、reduce-scatter、all-reduce，ep07）、PPBuffer（相邻 rank 之间收发，ep08）和 EngramBuffer（远程取数，ep08）。四者共用一套通信底座：NCCL Gin 设备端接口与对称内存窗口（ep05）。

  1. EP 第 1 篇ep01
    一个 EPBuffer 走完训练与推理：容量、展开布局、handle 与延迟尾声

    开头是 DeepEP 的库概览。正文讲接口语义：缓冲区要多大，dispatch 吐出的展开布局长什么样，handle 里存了什么，以及为什么 dispatch 的反向恰好是 combine。

    接口约 30 分钟先读：bg01
  2. EP 第 2 篇ep02
    直连模式的 dispatch：计数、布局、收发与拷贝尾声

    通知 warp 先数清每个专家要收多少 token；发送 warp 把 hidden、缩放因子和元数据打包成对齐的记录，直写对端缓冲区；最后由拷贝尾声展开成输出张量。

    数据通路约 17 分钟先读：ep01、bg02
  3. EP 第 3 篇ep03
    combine：BF16 归约、bias 与归约尾声

    把专家输出送回源 rank 并归约：没有 bias 且有效槽位不超过两个时走 BF16 直接相加的快路径，否则走 FP32 累加；bias 可以并进同一次归约。

    数据通路约 14 分钟先读：ep02
  4. EP 第 4 篇ep04
    NVLink 加 RDMA：混合模式的转发路径

    EP 组跨多个 NVLink 域时走两跳：先经 RDMA 送到目标域的代理节点，再经 NVLink 转发进最终的接收缓冲；combine 沿原路反向重放。

    数据通路约 15 分钟先读：ep02、bg02
  5. EP 第 5 篇ep05
    通信底座：NCCL Gin、对称内存窗口与内存序

    所有 EP 内核共用的地基：对 NCCL Gin 的一层薄封装，让同一 NVLink 域的 GPU 用指针直接读写对端内存的对称窗口，以及 ptx.cuh 里的内存序与屏障。

    通信底座约 15 分钟先读：ep02、ep04、bg02
  6. EP 第 6 篇ep06
    不调参：从拓扑和带宽算出 SM 与 QP，再交给 DeepJIT 现编

    SM 数与 QP 数不靠调参，而是由探测到的拓扑和带宽按公式算出。算出的整数是内核的模板实参，所以同时决定了 DeepJIT 要编译哪一份内核。

    资源估算约 21 分钟先读：ep05、bg02
  7. EP 第 7 篇ep07
    Bucket 集合通信：零 SM 的 all-gather 与 multimem 归约

    BucketBuffer 的三种集合通信。NVLink 上的 all-gather 完全交给复制引擎，不占 SM；节点内归约用一条 multimem.ld_reduce 指令完成。

    集合通信约 14 分钟先读：ep05、bg02
  8. EP 第 8 篇ep08
    冗余专家、Engram 与 PP：三种点对点搬运原语

    冗余专家的权重预取与梯度回收，加上两个实验性原语：按下标从远端表里取行的 Engram，和只在环上相邻 rank 之间收发的 PP。

    点对点原语约 23 分钟先读：ep01、ep05

DeepGEMM 卷：计算

DeepGEMM 是一个按需编译的 CUDA 内核库，内核分三类：基础 GEMM（FP8、FP4、BF16，dg01–dg03、dg06）、MoE 分组 GEMM（contiguous、masked、K 分组，dg04）和融合大内核（Mega MoE、Mega Gate、Mega mHC，dg08–dg09）。所有内核都由 host 端的启发式选配置，再经 DeepJIT 编译并缓存（dg05）。

  1. GEMM 第 1 篇dg01
    两级累加：Hopper 上的 FP8 GEMM 怎样把 scale 塞进流水线

    开头是 DeepGEMM 的库概览。正文讲 Hopper 上的 FP8 内核：张量核每次只算一个 128 宽的 K 块，乘上 scale 再并入第二组累加器；以及围绕它的 warp 特化与 mbarrier 流水线。

    基础内核 · Hopper约 20 分钟先读：bg02
  2. GEMM 第 2 篇dg02
    Blackwell 上的 FP8/FP4 GEMM：tcgen05、TMEM 与块缩放 MMA

    tcgen05.mma 取代 WGMMA：累加器和缩放因子都搬进张量内存（TMEM），线程分成搬运、MMA、UTCCP 转置、尾声四种角色；swap-AB 让不齐的 M 也能处理。

    基础内核 · Blackwell约 14 分钟先读：dg01
  3. GEMM 第 3 篇dg03
    缩放因子的格式学：UE8M0、MN-major 与 TMA 对齐

    缩放因子为什么必须是 2 的幂，四个 8 位指数怎样打包进一个 int32，变换后的张量怎样满足 TMA 的 16 字节对齐。

    数据格式约 13 分钟先读：dg02
  4. GEMM 第 4 篇dg04
    分组 GEMM 不换内核，只换索引表

    三种 MoE 分组 GEMM 共用一套内核，差别只在一张索引表存什么、调度器怎么读它。这张表和 DeepEP handle 里的前缀和是同一张，通信和计算就在这里接上。

    MoE 分组约 16 分钟先读：dg01、dg02、ep02
  5. GEMM 第 5 篇dg05
    配置怎么选、内核何时编：启发式、DeepJIT 与局部性域

    不做自动调参：host 侧枚举少量候选，淘汰不合法的，再选出一个。配置拼成源码交给 DeepJIT，先查内存与磁盘两级缓存，未命中才编译。

    配置与 JIT约 16 分钟先读：dg01–dg04
  6. GEMM 第 6 篇dg06
    没有 scale 的那一半：BF16、批量收缩、einsum 与 cuBLASLt 兜底

    去掉缩放因子，BF16 内核少一级累加，多出 FP32 输出与累加的能力。einsum 只认四条表达式；普通 BF16 GEMM 默认走 cuBLASLt。

    基础内核 · BF16约 14 分钟先读：dg01
  7. GEMM 第 7 篇dg07
    一条加权 ReLU，四种内核：Lightning Indexer 的 MQA logits

    索引器的分数是每个头的点积过 ReLU 再加权求和。按 KV 的取法（连续、分页、稀疏及其组合）有四个入口；SM90 与 SM100 处理缩放的方式不同。

    专用内核约 25 分钟先读：dg01–dg03
  8. GEMM 第 8 篇dg08
    Mega MoE：把一整层 MoE 塞进一个持久化内核

    dispatch、两层线性、SwiGLU 与再量化、combine 共六个阶段融合进一个持久化内核，通信与计算在同一组 SM 上交替执行；通信不走 NCCL，用 PyTorch 的对称内存。

    融合内核约 16 分钟先读：dg04、ep02、ep07
  9. GEMM 第 9 篇dg09
    Mega Gate、Mega mHC 与 TF32 HC prenorm GEMM

    Mega Gate 把门控 GEMM、打分和 top-k 选择融成一个内核，输出就是 dispatch 要的路由。Mega mHC 把 HyperConnection 的各步融合。另有一处 CUDA graph 重放下的屏障修复。

    融合内核约 16 分钟先读：dg02

阅读路径

两种选法：第一次接触这两个库，按难度分三段读；已经熟悉其中一部分，按关注点走捷径。

按难度，由浅入深

入门
bg01→bg02→导读→ep01→dg01约 70 分钟

MoE 为什么要通信，GPU 上有哪些部件，两个库各长什么样。读完能回答：EPBuffer 是什么，一个 GEMM 内核的骨架是什么。

进阶
ep02→ep03→dg02→dg03→dg04→dg06约 90 分钟

一层 MoE 的主干：token 怎样发出去、收回来，专家的矩阵乘在两代硬件上怎样算。读完能回答：一条 token 记录长什么样，专家收到的 token 数不齐时 GEMM 怎么排。

精通
ep04→ep05→ep06→dg05→ep07→ep08→dg07→dg08→dg09约 160 分钟

跨节点通信、通信底座、不调参的配置与 JIT，再到融合大内核。需要的背景最多：RDMA、内存序、CUDA graph。

按关注点，走捷径

做 EP 通信
ep01→ep02→ep03→ep04→ep05→ep06

一个 token 的完整往返，再到支撑它的通信底座与资源估算。

写 GEMM 内核
bg02→dg01→dg02→dg03→dg06→dg05

Hopper 与 Blackwell 两代内核的骨架、缩放因子格式、BF16 变体，最后看配置怎么选。

做推理与解码
ep01→dg04→dg08→dg09

不等 CPU 同步的 dispatch、能录进 CUDA graph 的 masked 布局、整层融合的 Mega MoE 与 Mega Gate。

只看两库怎么接上
ep01→dg04→dg08→ep06→dg05

三个交汇点：展开布局与分组 GEMM 共用的那张前缀和表，把通信搬进内核的 Mega MoE，两个仓库都用的 DeepJIT。

只有一小时
导读→ep01→dg04

两个库的分工、EP 的接口语义，以及通信与计算接上的那张索引表。
