Q1 · 平均 O(1)、期望 O(1)、摊还 O(1)、最坏 O(1) 有什么区别

5 条追问与解答
  • 四个词分别是对什么取平均？ 平均是对输入分布取平均（哈希表的 O(1) 假设 key 被哈希函数均匀打散，输入不配合就不成立）。期望是对算法自己掷的骰子取平均（跳表的层数、快排的随机 pivot），和输入无关，对手无法构造坏输入。摊还是一串操作的总代价除以次数，是确定性的保证，不含任何概率。最坏是单次操作的上界。所以强度排序是：最坏 > 摊还 > 期望 > 平均。
  • vector 为什么按倍数扩容，而不是每次多加固定大小？ 每次加 k 个：第 i 次扩容要拷贝 i · k 个元素，n 次插入总拷贝量是 k(1 + 2 + … + n/k)，即 O(n² / k)，摊还到每次是 O(n)。按倍数扩容时总拷贝量是等比数列 1 + 2 + 4 + … + n，和小于 2n，摊还 O(1)。关键在等比数列的和由最后一项主导。
  • 扩容因子取 2 还是 1.5？ 取 2 时，之前释放过的所有旧块大小之和是 1 + 2 + … + 2^(k-1) = 2^k - 1，永远比下一次要申请的 2^k 小，分配器无法拿这些旧块拼出新块，内存只能一直向后要。因子小于黄金比例 1.618 时，若干次扩容后旧块之和能装下新块，可以复用。libstdc++ 和 libc++ 取 2（拷贝次数少），MSVC 取 1.5（内存友好），没有绝对优劣。
  • 摊还 O(1) 在什么场景下不可接受？ 延迟敏感的场景。摊还保证的是总量，不限制单次：扩容或 rehash 的那一次是 O(n)，会在在线服务的 P99 上形成一个尖刺。对策是提前 reserve，或者把一次性的大搬迁拆散到后续每次操作里（Redis 的渐进式 rehash，见 第 5 节）。
  • 同样是 O(n)，遍历数组为什么比遍历链表快一个数量级？ 大 O 隐藏了常数，而这里的常数主要是访存。缓存行 64 字节，顺序读 int 数组时一次未命中能带回 16 个元素，硬件预取器还会提前把后面的行取好；链表节点在堆上分散，每跳一次指针都可能是一次未命中，主存访问延迟是一级缓存的上百倍。所以 n 在几千以内时，数组的 O(n) 操作经常比链表的 O(1) 操作还快。

2.数组与动态数组

  • 本质：一段连续内存。第 i 个元素的地址 = 基址 + i × 元素大小，一次乘加就能定位，所以随机访问是 O(1)。
  • 代价：中间插删要搬移后面所有元素，O(n)；容量不够时要整体搬家，搬家后原来的指针、引用、迭代器全部失效。
  • 优势常被低估：连续内存带来的缓存局部性，让它在中小规模下几乎总是最快的选择。不确定用什么容器时先用数组。
  • C++ 的 vector 细节（size 与 capacity、reserve 与 resize、emplace_back、迭代器失效规则、手写 vector）见 C++ 笔记 4.2 和 4.10。

// 手写动态数组（int 版）：容量不够就翻倍
class MyVector {
    int* data_ = nullptr;
    int size_ = 0, cap_ = 0;

    void grow() {
        int newCap = cap_ == 0 ? 1 : cap_ * 2;
        int* p = new int[newCap];                  // 申请新块，
        for (int i = 0; i < size_; ++i) p[i] = data_[i];   // 搬运，
        delete[] data_;                            // 释放旧块：旧指针、旧迭代器从这一刻起全部失效
        data_ = p;
        cap_ = newCap;
    }
public:
    ~MyVector() { delete[] data_; }
    void push_back(int x) {
        if (size_ == cap_) grow();
        data_[size_++] = x;
    }
    void pop_back() { --size_; }                   // 只改 size，不缩容
    int& operator[](int i) { return data_[i]; }
    int size() { return size_; }
    int capacity() { return cap_; }
};
// 二分模板：第一个 >= target 的位置，左闭右开 [lo, hi)。都比 target 小时返回 nums.size()
int lowerBound(vector<int>& nums, int target) {
    int lo = 0, hi = nums.size();
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;              // 不写 (lo + hi) / 2，避免相加溢出
        if (nums[mid] < target) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
// 34. 在排序数组中查找元素的第一个和最后一个位置：调两次模板
vector<int> searchRange(vector<int>& nums, int target) {
    int first = lowerBound(nums, target);
    if (first == (int)nums.size() || nums[first] != target) return {-1, -1};
    int last = lowerBound(nums, target + 1) - 1;   // 第一个 >= target + 1 的位置，再退一格
    return {first, last};
}
// 27. 移除元素：slow 指向下一个要写入的位置，fast 负责扫描。O(n)，不用 erase
int removeElement(vector<int>& nums, int val) {
    int slow = 0;
    for (int fast = 0; fast < (int)nums.size(); ++fast) {
        if (nums[fast] != val) nums[slow++] = nums[fast];
    }
    return slow;                                   // 新长度
}
  • 手写动态数组的追问点：扩容为什么是翻倍（见上面的 Q1）；pop_back 为什么不缩容（缩了之后紧接着再 push_back 又要扩，来回抖动）；这个类缺了拷贝构造和赋值，直接拷贝会让两个对象指向同一块内存、析构时重复释放。
  • 二分只背这一个模板就够了。 「最后一个不超过 x 的位置」是 lowerBound(x + 1) - 1，「x 是否存在」是看 lowerBound(x) 位置上的值，都能转成它。

Q2 · 数组的随机访问为什么是 O(1)，代价是什么

4 条追问与解答
  • 为什么下标从 0 开始？ 下标的含义是相对基址的偏移量，地址 = 基址 + i × 大小。如果从 1 开始，每次访问都要多做一次减法，或者浪费第 0 个槽位。
  • 扩容之后迭代器为什么失效？没扩容的 insert 呢？ 扩容 = 申请新块、搬运元素、释放旧块，旧迭代器本质上是指向旧块的指针，变成了悬垂指针。没扩容的 insert 也会让插入点之后的迭代器失效：内存没动，但元素整体后移了一格，迭代器指向的已经不是原来那个元素。
  • 二维数组按行遍历和按列遍历差多少，为什么？ C 和 C++ 是行主序，按行遍历是连续访存，一次缓存未命中之后的 15 个 int 都命中。按列遍历每一步跨过整整一行，步长远超缓存行，几乎每次访问都未命中。矩阵放不进缓存时，两者可以差几倍到十几倍。矩阵乘法调换循环顺序（ikj 代替 ijk）能提速，原因相同。
  • 怎么删除数组里所有满足条件的元素？ 用双指针把要保留的元素依次前移，最后一次性截掉尾部，O(n)；这就是 C++ 的 erase-remove 惯用法和 C++20 的 std::erase_if。在循环里逐个 erase 是 O(n²)，因为每删一个都要搬移后面全部元素，而且还要小心迭代器失效。

3.链表

  • 本质：节点分散在堆上，靠指针串联。已经拿到节点指针时，插入和删除只改几个指针，O(1)。
  • 代价：定位第 k 个要从头走，O(n)；每个节点多一到两个指针外加一次堆分配；访存跳跃，缓存不友好。
  • 真正适用的场景很窄：位置由别的结构直接给出（LRU 里哈希表给出节点）、需要 O(1) 拼接两条链、需要元素地址长期稳定、或者一个对象要同时挂在多条链上（侵入式链表）。
  • 五个必须默写的操作（反转、找中点、合并、判环与找入口、删除倒数第 k 个）和快慢指针找环入口的证明见 C++ 笔记 5.1。

struct ListNode {
    int val;
    ListNode* next;
    ListNode(int v) : val(v), next(nullptr) {}
};
// 206. 反转链表
ListNode* reverseList(ListNode* head) {
    ListNode* prev = nullptr;
    while (head) {
        ListNode* next = head->next;               // 先记住下一个，
        head->next = prev;                         // 再掉头
        prev = head;
        head = next;
    }
    return prev;
}
// 21. 合并两个有序链表
ListNode* mergeTwoLists(ListNode* a, ListNode* b) {
    ListNode dummy(0);                             // 哨兵：不用特判「结果链表的第一个节点」
    ListNode* tail = &dummy;
    while (a && b) {
        if (a->val <= b->val) { tail->next = a; a = a->next; }
        else { tail->next = b; b = b->next; }
        tail = tail->next;
    }
    tail->next = a ? a : b;                        // 剩下的一段直接接上
    return dummy.next;
}
// 19. 删除链表的倒数第 n 个节点：快指针先走 n 步，然后两个指针一起走
ListNode* removeNthFromEnd(ListNode* head, int n) {
    ListNode dummy(0);
    dummy.next = head;                             // 哨兵：要删的是头节点时也不用特判
    ListNode* fast = &dummy;
    ListNode* slow = &dummy;
    for (int i = 0; i < n; ++i) fast = fast->next;
    while (fast->next) { fast = fast->next; slow = slow->next; }
    slow->next = slow->next->next;                 // slow 停在被删节点的前一个
    return dummy.next;
}
// 142. 环形链表 II：快慢指针相遇后，一个指针回到头，两个同速再走，再次相遇的地方就是入口
ListNode* detectCycle(ListNode* head) {
    ListNode* slow = head;
    ListNode* fast = head;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {
            ListNode* p = head;
            while (p != slow) { p = p->next; slow = slow->next; }
            return p;
        }
    }
    return nullptr;                                // fast 走到了尽头，没有环
}

// 146. LRU 缓存：哈希表负责 O(1) 找到节点，双向链表负责 O(1) 调整顺序
class LRUCache {
    struct Node {
        int key, val;
        Node* prev;
        Node* next;
        Node(int k, int v) : key(k), val(v), prev(nullptr), next(nullptr) {}
    };
    int cap_;
    unordered_map<int, Node*> mp_;
    Node* head_;                                   // 两个哨兵：head_ 后面是最近用过的，tail_ 前面是最久没用的
    Node* tail_;

    void remove(Node* n) {
        n->prev->next = n->next;
        n->next->prev = n->prev;
    }
    void addFront(Node* n) {
        n->next = head_->next;
        n->prev = head_;
        head_->next->prev = n;
        head_->next = n;
    }
public:
    LRUCache(int capacity) : cap_(capacity) {
        head_ = new Node(0, 0);
        tail_ = new Node(0, 0);
        head_->next = tail_;
        tail_->prev = head_;
    }
    int get(int key) {
        if (!mp_.count(key)) return -1;
        Node* n = mp_[key];
        remove(n);                                 // get 也算「用过」，要挪到最前面
        addFront(n);
        return n->val;
    }
    void put(int key, int value) {
        if (mp_.count(key)) {
            Node* n = mp_[key];
            n->val = value;
            remove(n);
            addFront(n);
            return;
        }
        if ((int)mp_.size() == cap_) {
            Node* last = tail_->prev;              // 淘汰最久没用的
            remove(last);
            mp_.erase(last->key);                  // 节点里存 key，就是为了这一步能反查哈希表
            delete last;
        }
        Node* n = new Node(key, value);
        mp_[key] = n;
        addFront(n);
    }
};
  • LRU 的三个易错点：get 也要把节点挪到最前面；节点里必须存 key，否则淘汰尾节点时没法从哈希表里删掉它；put 一个已经存在的 key 是更新并挪到最前面，不是新增，不能触发淘汰。
  • 用 std::list 加迭代器的写法、加过期时间、加并发的追问见 C++ 笔记 5.5。

Q3 · 「链表插入是 O(1)」这句话的前提是什么

4 条追问与解答
  • 前提是什么？ 前提是已经拿到了插入位置的节点指针。如果要「在第 k 个位置插入」，定位本身就是 O(n)，整体和数组同阶；而且数组的 O(n) 是一次连续的 memmove，链表的 O(n) 是逐节点的缓存未命中，实测数组更快。所以链表只在「位置由别人直接给出」时才赢，例如 LRU 里由哈希表 O(1) 给出节点。
  • 哨兵节点解决什么问题？ 没有哨兵时，「在头部插入」「删除头节点」「链表为空」都需要单独判断，因为这些情况下要改的是 head 指针本身而不是某个节点的 next。加一个不存数据的哑节点之后，每个真实节点都有前驱，所有位置的插删代码变成同一种写法。边界分支是链表题出错最多的地方，哨兵直接把它们消掉。
  • 只给一个节点的指针，单链表能 O(1) 删掉它吗？ 能，但有限制：把后继节点的值拷贝过来，然后删除后继。原因是单链表拿不到前驱，就改成「让自己变成后继」。限制有三条：尾节点没有后继，做不到；外部如果还持有后继节点的指针，会悬垂；值很大时拷贝并不便宜。
  • 什么是侵入式链表，内核为什么用它？ 普通链表是「节点包着数据」，侵入式是把链表指针直接嵌进数据结构体里，再通过 offsetof 从指针成员反推出对象地址。好处有三个：一个对象可以同时挂在多条链上（就绪队列、等待队列、全局进程表）而不需要为每条链各分配一个节点；拿到对象就能 O(1) 把自己从链上摘下来，不用查找；挂链、摘链不涉及内存分配，所以不会失败，这在中断上下文里是硬要求。

4.栈、队列与双端队列

  • 栈：数组尾部进出即可，压栈和弹栈都是 O(1)。
  • 队列：数组实现必须做成环形缓冲区（头尾下标对容量取模），否则出队要搬移元素；链表实现需要同时记头尾指针。
  • std::deque：分段连续。一个中控数组存着若干个定长缓冲块的指针，头尾各自向外生长，不需要搬移已有元素。
  • 适配器的默认底层：stack 和 queue 默认用 deque，priority_queue 默认用 vector。
  • 单调栈 / 单调队列：在栈或队列里只保留「将来还有可能成为答案」的元素，其余提前淘汰。

// 739. 每日温度（单调栈）：栈里放下标，对应的温度从栈底到栈顶递减
vector<int> dailyTemperatures(vector<int>& t) {
    int n = t.size();
    vector<int> res(n, 0);
    stack<int> st;
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && t[i] > t[st.top()]) {   // t[i] 就是栈顶那天之后第一个更高的温度
            res[st.top()] = i - st.top();
            st.pop();
        }
        st.push(i);
    }
    return res;
}
// 239. 滑动窗口最大值（单调队列）：队列里放下标，对应的值从队头到队尾递减
vector<int> maxSlidingWindow(vector<int>& nums, int k) {
    deque<int> dq;
    vector<int> res;
    for (int i = 0; i < (int)nums.size(); ++i) {
        while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back();   // 比新元素小又比它老，不可能再当最大值
        dq.push_back(i);
        if (dq.front() <= i - k) dq.pop_front();                           // 队头已经滑出窗口
        if (i >= k - 1) res.push_back(nums[dq.front()]);                   // 队头就是当前窗口的最大值
    }
    return res;
}
  • 单调栈和单调队列里存的都是下标，不是值。 原因是答案需要距离（739）或者需要判断元素是否已经滑出窗口（239），这两件事只有下标能提供；值随时可以通过下标取到。
  • 239 里弹队尾用 <=。 相等的旧元素也弹掉，因为新元素和它一样大却更晚过期，旧的那个已经没有留着的价值。

Q4 · std::deque 怎么做到两端 O(1) 插入，同时还支持随机访问

5 条追问与解答
  • 内部结构是什么？ 中控数组加若干个定长缓冲块。下标 i 先换算成（第几块，块内偏移），再取两次地址，所以随机访问是 O(1)，但比 vector 多一次间接寻址。头部空间不够时在中控数组前面再挂一个新块，已有元素不动，这是它头插 O(1) 的原因。
  • 两端插入之后，迭代器和引用哪个会失效？ 迭代器全部失效，但元素的引用和指针不失效。原因是迭代器里存着指向中控数组的指针，而中控数组满了会重新分配；元素本身所在的缓冲块从不搬家，所以指向元素的指针一直有效。这是 deque 和 vector 最容易被问到的区别。
  • stack 只需要在尾部操作，为什么默认底层不是 vector？ deque 增长时只是多挂一个块，不搬移已有元素；vector 扩容要整体拷贝，而且拷贝的瞬间新旧两块同时存在，峰值内存接近三倍。作为通用默认值，deque 的最坏情况更温和。明确知道规模时，stack<int, vector<int>> 加 reserve 更快。
  • 单调栈为什么是 O(n)，栈里为什么要保持单调？ 每个元素只进栈一次、出栈一次，总操作数不超过 2n。以「右边第一个更大的元素」为例：新元素到来时，栈里所有比它小的元素都找到了答案（就是它），可以弹出；剩下的都比它大，还没遇到自己的答案，继续留着。弹完之后栈自然是单调递减的，单调性是这个淘汰规则的结果而不是额外的要求。
  • 滑动窗口最大值为什么要用双端队列？ 需要在两端删除：新元素进来时，从队尾弹出所有不大于它的元素，因为它们比新元素更早过期而且更小，永远不可能再成为最大值；窗口滑动时，从队头弹出已经滑出窗口的元素。队头始终是当前窗口的最大值。每个元素进出各一次，总体 O(n)。

5.哈希表

三个设计决策：哈希函数（怎么把 key 打散）、冲突解决（两个 key 落到同一个位置怎么办）、扩容策略（什么时候、怎么搬）。

拉链法 开放寻址（线性探测为主）
冲突处理 每个桶挂一条链表 顺着数组往后找下一个空位
负载因子 可以大于 1，通常阈值 0.75 到 1 必须小于 1，通常阈值 0.5 到 0.875

  • 什么时候不用哈希表：需要有序遍历、范围查询、找前驱后继；需要最坏情况也有保证；数据量很小（几十个元素以内线性扫描数组更快）。

手写哈希表（拉链法），以及哈希表最典型的两种用法：用空间换一次查找（两数之和），用集合把「判断是否存在」降到 O(1)（最长连续序列）。

// 706. 设计哈希映射：拉链法。key 保证非负
class MyHashMap {
    static const int B = 1009;                     // 桶数取质数
    vector<list<pair<int, int>>> buckets_;
public:
    MyHashMap() : buckets_(B) {}
    void put(int key, int value) {
        auto& chain = buckets_[key % B];
        for (auto& kv : chain) {
            if (kv.first == key) { kv.second = value; return; }   // 已存在就更新
        }
        chain.push_back({key, value});
    }
    int get(int key) {
        for (auto& kv : buckets_[key % B]) {
            if (kv.first == key) return kv.second;
        }
        return -1;
    }
    void remove(int key) {
        auto& chain = buckets_[key % B];
        for (auto it = chain.begin(); it != chain.end(); ++it) {
            if (it->first == key) { chain.erase(it); return; }
        }
    }
};
// 1. 两数之和
vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int, int> pos;                   // 值 -> 下标
    for (int i = 0; i < (int)nums.size(); ++i) {
        if (pos.count(target - nums[i])) return {pos[target - nums[i]], i};
        pos[nums[i]] = i;                          // 先查后存，避免自己和自己配对
    }
    return {};
}
// 128. 最长连续序列
int longestConsecutive(vector<int>& nums) {
    unordered_set<int> s(nums.begin(), nums.end());
    int best = 0;
    for (int x : s) {
        if (s.count(x - 1)) continue;              // 只从每一段的起点开始数，每个数最多被数一次，总体 O(n)
        int len = 1;
        while (s.count(x + len)) ++len;
        best = max(best, len);
    }
    return best;
}
  • 手写哈希表的追问点：桶数为什么取质数（见上面的要点）；负数 key 怎么办（C++ 里负数取模结果为负，要写成 (key % B + B) % B）；怎么扩容（元素个数超过桶数乘以负载因子时，新建一个更大的桶数组，把每个元素重新取模放进去）。带扩容和分段加锁的版本见 C++ 笔记 5.2。
  • 128 为什么是 O(n)？ 外层循环虽然套着一个 while，但只有「每一段的起点」才会进入 while，每个数最多被某一段数到一次，总次数不超过 n。

Q5 · 拉链法和开放寻址怎么选

4 条追问与解答
  • 开放寻址的删除为什么要留墓碑？ 查找靠「探测到空槽就停」来判断 key 不存在。如果把被删的槽直接清空，经过这个槽的探测链就被截断了，排在它后面的 key 再也找不到。墓碑的含义是「这里曾经有人，请继续往后找」。墓碑不会自己消失，积累多了查找变慢，只能靠 rehash 清理，这是开放寻址在删除频繁的场景下的主要代价。
  • 线性探测的聚集是怎么回事？ 一段连续被占的槽位越长，新 key 撞进这一段的概率就越大（落在段内任何位置都会被排到段尾），于是这一段变得更长，是正反馈。成功查找的期望探测次数约为 (1 + 1/(1 - α)) / 2，失败查找约为 (1 + 1/(1 - α)²) / 2：负载因子 α 为 0.5 时分别是 1.5 和 2.5 次，到 0.9 时变成 5.5 和 50.5 次。这就是开放寻址的扩容阈值必须比拉链法低的原因。
  • 明知会聚集，为什么线性探测仍然是最常用的探测方式？ 因为它探测的是相邻内存，一次缓存未命中载入的 64 字节能覆盖好几个槽位，后续几次探测都在缓存里。二次探测和双重哈希能缓解聚集，但每一步都跳到远处，每次探测都可能未命中。在现代硬件上访存代价远大于比较代价，缓存优势盖过了聚集劣势。
  • std::unordered_map 为什么公认比较慢？ 标准规定了两件事：rehash 之后指向元素的引用和指针必须仍然有效，以及必须提供按桶遍历的接口。这两条实际上强制了「每个元素一个独立分配的节点」的拉链实现，于是每次查找至少两次指针跳转，每次插入一次 malloc。absl 的 flat_hash_map 放弃了引用稳定性，把元素平铺在数组里，并用每槽一字节的控制信息配合 SIMD 一次比较 16 个槽，通常快两倍以上。

Q6 · 哈希表扩容时发生了什么

4 条追问与解答
  • 负载因子的阈值为什么不设得很高来省内存？ 拉链法下平均链长就等于负载因子 α，一次查找的期望代价是 O(1 + α)。α 是一个用空间换时间的旋钮：调高省内存但链变长，调低则相反。0.75 到 1 是经验上的折中点。
  • rehash 为什么要重新计算每个元素的位置？ 桶号 = 哈希值 % 桶数，桶数变了结果就变了。桶数是 2 的幂并且每次翻倍时有一个好性质：元素要么留在原来的桶 i，要么去 i + 旧容量，只取决于哈希值里新露出来的那一位。Java 8 利用这一点，扩容时不重新取模，直接把一条链按那一位拆成两条。
  • Redis 的渐进式 rehash 是怎么做的，为什么要这样？ 一次性搬迁是 O(n)，Redis 是单线程，几百万个 key 的表一搬就是一次明显的停顿。做法是新旧两张表并存，之后每次增删改查顺带搬一个桶，后台定时任务再补一些。期间查找要查两张表；新插入只进新表，保证旧表只减不增，搬迁一定能结束。本质是把摊还分析里那一笔大额开销，真的摊到了每次操作上。
  • unordered_map rehash 之后，迭代器和引用还有效吗？ 迭代器失效，引用和指针仍然有效。原因是 rehash 只是把节点重新挂到新的桶数组上，节点本身没有移动，所以指向元素的指针不变；而迭代器的遍历顺序依赖桶的排布，排布变了就不再可靠。

Q7 · 哈希表最坏 O(n)，工程上怎么防

3 条追问与解答
  • 什么是哈希洪水攻击？ 哈希函数是公开的，攻击者可以离线构造出大量落进同一个桶的 key，通过请求参数之类的入口塞进服务端的哈希表，让每次插入从 O(1) 退化成 O(n)，n 个 key 总共 O(n²)，几 KB 的请求就能吃满一个 CPU 核。
  • 怎么防？ 两条路。一是让攻击者无法预测哈希值：进程启动时生成随机种子，用带密钥的哈希函数（SipHash），Python 和 Rust 默认如此。二是限制最坏情况：Java 8 在单个桶的链长达到 8 且表容量不小于 64 时，把链表转成红黑树，最坏从 O(n) 变成 O(log n)。
  • Java 的树化阈值为什么是 8，退回链表为什么是 6？ 哈希均匀时，桶内元素个数近似服从参数 0.5 的泊松分布，链长达到 8 的概率约为一亿分之六，正常情况下几乎不会触发，树化只是给攻击或劣质哈希函数兜底。不一开始就用树，是因为树节点的体积大约是普通节点的两倍。8 和 6 之间留出间隔，是为了避免元素个数在边界上下波动时反复转换。

Q8 · 一致性哈希解决什么问题

3 条追问与解答
  • 直接用 hash(key) % N 分片有什么问题？ N 一变，几乎所有 key 的归属都变了。对缓存集群来说等于全部缓存同时失效，请求一起打到后端，就是缓存雪崩。一致性哈希把 key 和节点都映射到同一个环上，key 归顺时针方向遇到的第一个节点；增删一个节点只影响它和前一个节点之间那一段，平均只有 1/N 的 key 需要迁移。
  • 为什么需要虚拟节点？ 节点数少的时候，几个点在环上的分布很不均匀，有的节点会分到远多于平均的一段。让每个物理节点在环上放一两百个虚拟节点，各段长度就趋于平均；节点下线时它的负载也会分散给很多节点，而不是全部压给顺时针的下一个。调整虚拟节点的数量还能表达权重。
  • 用什么数据结构实现？ 有序映射，key 是环上的位置，value 是节点。查找就是 lower_bound(hash(key))，走到末尾就回绕到 begin()，O(log N)。推理服务里按 prompt 前缀做缓存亲和路由，用的也是这一套：同一前缀稳定地路由到同一个实例，实例增减时只有少量前缀需要重新预热。

6.堆与优先队列

  • 本质：一棵完全二叉树，只保证父节点不小于（或不大于）孩子，兄弟之间没有顺序要求。
  • 存储：完全二叉树没有空洞，直接按层存进数组。下标从 0 开始时，父节点是 (i - 1) / 2，孩子是 2i + 1 和 2i + 2，不需要任何指针。
  • 两个基本动作：上浮（插入到末尾之后和父节点比较交换）和下沉（删除堆顶后把末尾元素放到根，和较大的孩子比较交换），都是 O(log n)。
  • C++ 里怎么用、怎么手写：std::priority_queue 的用法见 6.1；手写有两个版本（都是面试可手写的 int 版），有序数组（快排 + 二分）见 6.2，二叉堆见 6.3，取舍见 6.4；堆排序和第 K 大见 6.5。
  • 不支持：查找任意元素、删除任意元素、有序遍历。需要这些就换平衡树，或者用懒删除（旧元素留在堆里，出堆时再判断它是否已经过期）。

Q9 · 建堆为什么是 O(n) 而不是 O(n log n)

5 条追问与解答
  • O(n) 怎么来的？ 自底向上，对每个非叶子节点做一次下沉。高度为 h 的节点最多下沉 h 层，而这样的节点大约有 n / 2^(h+1) 个，总代价是对 h · n / 2^(h+1) 求和，这个级数收敛到 O(n)。直觉是：一半的节点是叶子完全不用动，四分之一的节点只下沉一层，需要走完整棵树高度的只有根一个。逐个插入的建法正好相反，占多数的底层节点每个都可能上浮 log n 层，所以是 O(n log n)。
  • 求最大的 K 个元素，为什么用小顶堆？ 维护一个大小为 K 的堆，保存目前见过的最大的 K 个。新元素来的时候要回答的问题是「它能不能挤掉这 K 个里最小的那个」，所以需要快速拿到的是 K 个里的最小值，也就是小顶堆的堆顶。它相当于一道门槛：不高于门槛的直接丢弃，高于门槛的替换堆顶。
  • Top K 用堆还是快速选择？ 堆是 O(n log K)，空间 O(K)，数据可以流式到来，也不要求全部装进内存。快速选择平均 O(n)，但要求数据全在内存里、会打乱原数组，而且最坏 O(n²)（随机选 pivot 可以让最坏情况不依赖输入）。海量数据或数据流只能用堆；一次性的内存内计算用快速选择更快。
  • 堆为什么不能 O(log n) 查找任意元素？ 堆只约束了父子之间的大小关系，左右子树之间没有任何关系，要找的值可能在任意一边，只能遍历，O(n)。这也是 priority_queue 不提供删除任意元素的原因：删除本身是 O(log n)，但先得 O(n) 找到它。
  • 定时器用堆还是时间轮？ 堆的插入和删除都是 O(log n)，取最近到期的是 O(1)，精度任意，Go 运行时用的是四叉堆。时间轮把时间切成固定的格子，每格挂一条链表，插入和删除都是 O(1)，适合数量巨大、精度要求固定的定时器（比如连接超时），代价是精度受格子大小限制；Linux 内核、Kafka、Netty 用的是时间轮。四叉堆相比二叉堆更矮，而且四个孩子在数组里相邻，能落在同一个缓存行里。

6.1 std::priority_queue 的用法

头文件 <queue>。完整的模板签名是 priority_queue<T, Container = vector<T>, Compare = less<T>>：它不是一个独立的容器，而是套在 vector 外面的适配器，内部就是对这个 vector 调用 push_heap 和 pop_heap。

操作 复杂度 说明
push(x) O(log n)
top() O(1) 只读；空队列上调用是未定义行为，不会抛异常
pop() O(log n) 返回 void；空队列上调用同样是未定义行为
size() / empty() O(1)
构造 pq(v.begin(), v.end()) O(n) 直接建堆，比逐个 push 的 O(n log n) 快

基本用法

void basicUsage() {
    priority_queue<int> maxHeap;                               // 默认是大顶堆
    maxHeap.push(3);
    maxHeap.push(5);
    maxHeap.push(1);
    assert(maxHeap.top() == 5);                                // top() 只看不删
    maxHeap.pop();                                             // pop() 只删不返回：先 top() 取值，再 pop()
    assert(maxHeap.top() == 3 && maxHeap.size() == 2);

    priority_queue<int, vector<int>, greater<int>> minHeap;    // 小顶堆：三个模板参数必须写全
    minHeap.push(3);
    minHeap.push(1);
    minHeap.push(4);
    assert(minHeap.top() == 1);

    vector<int> v = {9, 2, 7, 4};
    priority_queue<int> fromVec(v.begin(), v.end());           // 用一段数据直接建堆，O(n)；逐个 push 是 O(n log n)
    assert(fromVec.top() == 9);

    priority_queue<pair<int, string>> byPair;                  // pair 先比 first，相等再比 second
    byPair.push({2, "b"});
    byPair.push({2, "c"});
    byPair.push({1, "z"});
    assert(byPair.top().second == "c");

    while (!maxHeap.empty()) maxHeap.pop();                    // 没有 clear()，只能一个个弹空
}

自定义比较器的三种写法

比较器的方向是最容易写反的地方。规则只有一条：cmp(a, b) 返回 true 表示 a 的优先级比 b 低。所以 less 得到大顶堆，greater 得到小顶堆。一个可靠的记法：把同一个比较器交给 sort，排在最后的那个元素就是堆顶。

struct Task {
    int priority;
    string name;
};

// 写法一：仿函数。cmp(a, b) 返回 true 表示「a 的优先级比 b 低」，和 less 同一个方向
struct TaskCmp {
    bool operator()(const Task& a, const Task& b) { return a.priority < b.priority; }   // priority 大的先出
};

void customUsage() {
    priority_queue<Task, vector<Task>, TaskCmp> q1;
    q1.push({1, "low"});
    q1.push({5, "high"});
    assert(q1.top().name == "high");

    // 写法二：lambda。类型用 decltype(cmp)，并且要把 cmp 传给构造函数
    auto cmp = [](const Task& a, const Task& b) { return a.priority > b.priority; };    // 反过来：priority 小的先出
    priority_queue<Task, vector<Task>, decltype(cmp)> q2(cmp);
    q2.push({3, "c"});
    q2.push({1, "a"});
    assert(q2.top().name == "a");

    // 写法三：不写比较器，直接用 pair，把要比的字段放在 first；存负数就能把大顶堆当小顶堆用
    priority_queue<pair<int, int>> q3;                         // {-距离, 节点}：距离最小的在堆顶
    q3.push({-7, 1});
    q3.push({-2, 2});
    assert(q3.top().second == 2);
}

// 模式一：最大的 K 个 → 大小为 K 的小顶堆，堆顶是「入选门槛」
vector<int> topK(vector<int>& nums, int k) {
    priority_queue<int, vector<int>, greater<int>> pq;
    for (int x : nums) {
        pq.push(x);
        if ((int)pq.size() > k) pq.pop();                      // 超过 K 个就踢掉最小的
    }
    vector<int> res;
    while (!pq.empty()) { res.push_back(pq.top()); pq.pop(); }
    return res;                                                // 从小到大
}

// 模式二：合并 K 个有序链表。堆里放的是指针，必须自己写比较器去比 val，否则比的是地址
struct ListNode {
    int val;
    ListNode* next;
    ListNode(int v) : val(v), next(nullptr) {}
};

ListNode* mergeKLists(vector<ListNode*>& lists) {
    auto cmp = [](ListNode* a, ListNode* b) { return a->val > b->val; };   // val 小的先出
    priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> pq(cmp);
    for (ListNode* head : lists) {
        if (head) pq.push(head);                               // 空链表不能进堆，否则比较器会解引用空指针
    }
    ListNode dummy(0);
    ListNode* tail = &dummy;
    while (!pq.empty()) {
        ListNode* node = pq.top();
        pq.pop();
        tail->next = node;
        tail = node;
        if (node->next) pq.push(node->next);
    }
    return dummy.next;
}

priority_queue 内部在做什么

它只是在 vector 上调用 <algorithm> 里的两个堆算法。知道这一点，6.3 的手写版本就只是把这两个算法自己实现一遍。

void heapAlgoUsage() {
    vector<int> h;
    for (int x : {3, 8, 5}) {
        h.push_back(x);                                        // 先放到末尾，
        push_heap(h.begin(), h.end());                         // 再让它上浮；push() 内部就是这两步
    }
    pop_heap(h.begin(), h.end());                              // 把堆顶换到末尾，前面 n - 1 个重新成堆
    int best = h.back();                                       // 此时末尾就是原来的最大值
    h.pop_back();                                              // pop() 内部就是 pop_heap + pop_back
    assert(best == 8 && h.front() == 5);
}

易错点清单

  • 方向写反。 less 是大顶堆，greater 是小顶堆。
  • 小顶堆少写模板参数。 比较器是第三个参数，想指定它就必须把第二个参数 vector<T> 也写出来。
  • 空队列上调用 top() 或 pop()。 是未定义行为而不是异常，通常表现为读到垃圾值或崩溃。循环条件里先判 empty()。
  • 想修改已经入队的元素。 做不到。要改优先级只能重新 push 一份新的，再用懒删除跳过旧的。
  • 比较器里写 <=，或者照 Java 的习惯写 return a.x - b.x。 前者违反严格弱序；后者在 C++ 里会被转成 bool，非零即真，cmp(a, b) 和 cmp(b, a) 同时为真，同样违反严格弱序，是未定义行为。
  • 元素是指针却没写比较器。 默认比较的是地址，能编译、能运行，结果是错的，而且每次运行还不一样。

Q10 · priority_queue 的接口为什么设计成这样

6 条追问与解答
  • less 为什么得到的是大顶堆，这不是反了吗？ 没有反，它和 sort 用的是同一套语义：cmp(a, b) 为真表示 a 排在 b 的前面。sort 配 less 得到升序，最大的元素排在最后；priority_queue 取出的正是「排在最后」的那个元素。标准库这样设计，是为了让同一个比较器在 sort、set、priority_queue 里含义一致，代价是堆这里读起来反直觉。
  • pop() 为什么不直接返回被弹出的元素？ 为了异常安全。如果 pop 按值返回，流程是先把元素从容器里移除，再拷贝构造返回值；要是拷贝构造抛了异常，元素已经不在队列里，又没有交到调用者手上，就丢了。拆成 top() 和 pop() 两步之后，任何一步失败都不会丢数据。stack 和 queue 同理。
  • 为什么不能遍历、不能删除任意元素？ 它是适配器，只暴露「优先队列」这个抽象允许的操作。堆数组里的顺序既不是有序的，也不是插入顺序，遍历出来没有意义；删除任意元素需要先 O(n) 找到它，违背了这个结构的复杂度承诺。确实需要这些能力时，自己用 vector 加上面两个堆算法，或者换成 set。
  • 比较器里写 <= 会怎样？ 未定义行为。标准要求比较器是严格弱序，其中一条是 cmp(a, a) 必须为假。堆算法和排序算法内部都用「cmp(a, b) 和 cmp(b, a) 同时为假」来判定两个元素相等，<= 让两个相等的元素互相「小于」对方，这套推理就不成立了。在 sort 里同样的错误更危险，可能直接越界访问。
  • 用 lambda 做比较器时，为什么还要把它传给构造函数？ 模板参数 decltype(cmp) 只提供了类型，priority_queue 内部还需要一个这个类型的对象。C++17 及以前，lambda 没有默认构造函数，所以必须传一个现成的对象进去让它拷贝。C++20 起没有捕获的 lambda 可以默认构造，可以不传。
  • 底层容器能换成 list 吗？ 不能，vector 和 deque 可以。原因是堆靠下标运算 (i - 1) / 2 和 2i + 1 来定位父子节点，必须能 O(1) 随机访问。默认选 vector 而不是 deque，是因为上浮和下沉是跳跃式访问，vector 是单块连续内存，deque 每次访问还要多一层间接寻址。

6.2 手搓优先队列之一：快排 + 二分（有序数组）

思路是让数组始终保持升序：一批数据进来时用快排一次排好，之后每插入一个元素，用二分找到位置再插进去。最大的元素固定在数组末尾，top 和 pop 都是 O(1)。

下面是面试里能直接手写的版本：只处理 int，大的优先。要小的优先，把两处比较反过来，或者存相反数。

40 行 · 点击折叠
// 手搓优先队列，版本一：有序数组。批量建表用快排，单个插入用二分找位置。大的优先。
class SortedPQ {
    vector<int> a;                                 // 不变量：升序，最大的在末尾

    void quickSort(int l, int r) {
        if (l >= r) return;
        int pivot = a[l + rand() % (r - l + 1)];   // 随机选基准，有序输入也不会退化
        int i = l, j = r;
        while (i <= j) {
            while (a[i] < pivot) ++i;              // 左边找一个不该在左边的
            while (a[j] > pivot) --j;              // 右边找一个不该在右边的
            if (i <= j) swap(a[i++], a[j--]);
        }
        quickSort(l, j);                           // 此时 j < i，[l, j] 都不大于 pivot，[i, r] 都不小于 pivot
        quickSort(i, r);
    }

    int lowerBound(int x) {                        // 第一个 >= x 的位置，左闭右开 [lo, hi)
        int lo = 0, hi = a.size();
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (a[mid] < x) lo = mid + 1;
            else hi = mid;
        }
        return lo;
    }

public:
    SortedPQ() {}
    SortedPQ(vector<int> nums) : a(nums) { quickSort(0, (int)a.size() - 1); }

    void push(int x) {
        int pos = lowerBound(x);                   // 二分找位置：O(log n)
        a.insert(a.begin() + pos, x);              // 插入要搬移后面的元素：O(n)
    }
    int top() { return a.back(); }
    void pop() { a.pop_back(); }                   // 尾删 O(1)，所以让最大的待在末尾
    bool empty() { return a.empty(); }
    int size() { return a.size(); }
};

快排部分四个容易写错的地方：

  • 基准要随机选。 固定取第一个元素，遇到已经有序的输入时每轮只能划掉一个元素，退化成 O(n²)，而「本来就排好序的任务列表」恰好是优先队列最常见的输入。
  • 内层两个 while 必须是 < 和 >，不能带等号。 带了等号，数组元素全部相等时 i 会一路冲出数组右端。不带等号时，和基准相等的元素会被交换到对面去，两个指针总能停下来。
  • 内层 while 为什么不用判断越界？ 基准是区间里真实存在的一个值，第一轮 i 最晚走到它的位置就会停，j 同理。之后每次交换，都会在 i 的右边留下一个不小于基准的数、在 j 的左边留下一个不大于基准的数，它们就是下一轮的「挡板」。
  • 递归区间是 [l, j] 和 [i, r]。 循环结束时 j 小于 i，j 及其左边都不大于基准，i 及其右边都不小于基准。写成 [l, i] 会在区间只剩两个元素时无限递归。

二分部分用「左闭右开」写法：hi 初始为 size()，循环条件 lo < hi，收缩时 hi = mid。找的是第一个不小于 x 的位置，x 比所有元素都大时自然返回 size()，正好是 insert 到末尾的位置，不需要特判。

6.3 手搓优先队列之二：二叉堆

这才是 std::priority_queue 的真实做法。同样是只处理 int 的大顶堆，要小顶堆就把 siftUp 和 siftDown 里的三处比较反过来。

把数组看成一棵完全二叉树：下标 i 的父节点是 (i - 1) / 2，两个孩子是 2i + 1 和 2i + 2。

44 行 · 点击折叠
// 手搓优先队列，版本二：二叉堆（大顶堆）。std::priority_queue 的真实做法。
class MaxHeap {
    vector<int> a;                                 // 不变量：每个节点都不小于它的两个孩子

    void siftUp(int i) {
        while (i > 0) {
            int p = (i - 1) / 2;                   // 父节点
            if (a[p] >= a[i]) break;
            swap(a[p], a[i]);
            i = p;
        }
    }
    void siftDown(int i) {
        int n = a.size();
        while (true) {
            int big = i, l = 2 * i + 1, r = 2 * i + 2;
            if (l < n && a[l] > a[big]) big = l;
            if (r < n && a[r] > a[big]) big = r;   // 要和两个孩子里较大的那个交换
            if (big == i) break;
            swap(a[i], a[big]);
            i = big;
        }
    }

public:
    MaxHeap() {}
    MaxHeap(vector<int> nums) : a(nums) {
        int n = a.size();
        for (int i = n / 2 - 1; i >= 0; --i) siftDown(i);      // 从最后一个非叶子节点倒着下沉，O(n)
    }

    void push(int x) {
        a.push_back(x);                            // 先放到末尾，
        siftUp(a.size() - 1);                      // 再上浮
    }
    int top() { return a[0]; }
    void pop() {
        a[0] = a.back();                           // 末尾元素顶替堆顶，
        a.pop_back();
        if (!a.empty()) siftDown(0);               // 再下沉
    }
    bool empty() { return a.empty(); }
    int size() { return a.size(); }
};

三个要点：

  • pop 是「末尾元素顶替堆顶，删掉末尾，再从根下沉」。 直接删除数组头部要搬移全部元素，而且会破坏完全二叉树的形状；用末尾元素顶上来，形状不变，只需要修复根节点这一处的大小关系。
  • 下沉时必须和两个孩子里较大的那个交换。 如果和较小的那个交换，它上去之后比另一个孩子小，不变量仍然是坏的。
  • 建堆的循环从 n / 2 - 1 开始倒着做。 下标不小于 n / 2 的全是叶子，单个节点天然是合法的堆，不需要处理。倒着做是为了保证处理某个节点时，它的两棵子树已经是合法的堆。这样建堆是 O(n)，原因见上面的 Q9。

Q11 · 不用堆怎么实现优先队列，和堆相比各自赢在哪

6 条追问与解答
  • 有序数组版的 push 已经用了二分，为什么还是 O(n)？ 二分只是把「找位置」降到了 O(log n)，但 insert 要把插入点之后的元素整体后移一格，搬移量是 O(n)。瓶颈从比较转移到了搬移。
  • 为什么把最大的元素放在数组末尾，而不是开头？ vector 只有尾部的删除是 O(1)。放在末尾，top 是 back()，pop 是 pop_back()；放在开头的话，每次 pop 都要搬移剩下的全部元素。底层容器在哪一端操作便宜，就让最频繁的操作落在哪一端。
  • 什么情况下有序数组版反而比堆合适？ 三种情况。先一次性装入、之后几乎只出队：一次排序之后每次 pop 是 O(1)，堆每次是 O(log n)。需要同时取最大和最小，或者取第 k 大：数组两端分别是最小和最大，第 k 大是一次下标访问，堆都做不到。n 很小（几十个以内）：整个数组只占几个缓存行，搬移是一次 memmove，比堆的分支跳转还快。
  • 那为什么通用场景下堆才是正解？ 堆只维护「父节点不小于孩子」这一条关系，不要求兄弟之间、子树之间有序。优先队列对外只承诺「能取到最大的那个」，这点关系已经足够。有序数组维护的是全体有序，信息量超出了优先队列的需要，多出来的那部分就是每次插入白付的 O(n)。数据结构维护的信息越少，维护代价越低，选型时要让它恰好等于需求。
  • 堆的 push 为什么说平均是 O(1)？ 完全二叉树里一半的节点是叶子，四分之一在倒数第二层。一个随机的新元素大概率比不过它的父节点，上浮一两层就停了，平均比较次数是一个小常数（约 2 到 3 次）。O(log n) 是一路浮到根的最坏情况，比如按递增顺序往大顶堆里插入。pop 没有这个好处：顶上来的是原来的末尾元素，通常很小，几乎总要沉到底。
  • 元素换成带优先级的结构体，优先级相同时要求先进先出，两种实现各怎么做？ 有序数组版不用改结构：二分找的是第一个不小于 x 的位置，新元素会插在所有同优先级元素的前面，而出队是从末尾取，所以同优先级里先来的先出。唯一要注意的是快排不稳定，初始那一批数据里同优先级的顺序会被打乱，要么改用归并排序，要么加入队序号。堆做不到，因为上浮和下沉会打乱相同元素的相对顺序，只能给每个元素加一个递增的入队序号，比较时优先级相同就比序号。

6.5 堆排序与第 K 大

堆的两道高频手撕题。堆排序复用 6.3 的下沉；第 K 大（215）面试官通常期望快速选择，用堆做是保底方案。

// 堆排序：原地，O(n log n)，不稳定
void siftDown(vector<int>& a, int n, int i) {      // 在 a[0..n) 这个堆里把 i 号节点往下沉
    while (true) {
        int big = i, l = 2 * i + 1, r = 2 * i + 2;
        if (l < n && a[l] > a[big]) big = l;
        if (r < n && a[r] > a[big]) big = r;
        if (big == i) break;
        swap(a[i], a[big]);
        i = big;
    }
}
void heapSort(vector<int>& a) {
    int n = a.size();
    for (int i = n / 2 - 1; i >= 0; --i) siftDown(a, n, i);   // 建大顶堆
    for (int end = n - 1; end > 0; --end) {
        swap(a[0], a[end]);                        // 当前最大的换到末尾，它就位了
        siftDown(a, end, 0);                       // 前面 end 个重新成堆
    }
}
// 215. 数组中的第 K 个最大元素：快速选择，平均 O(n)
int quickSelect(vector<int>& a, int l, int r, int k) {        // 返回排好序后下标为 k 的那个数
    if (l == r) return a[l];
    int pivot = a[l + rand() % (r - l + 1)];
    int i = l, j = r;
    while (i <= j) {
        while (a[i] < pivot) ++i;
        while (a[j] > pivot) --j;
        if (i <= j) swap(a[i++], a[j--]);
    }
    if (k <= j) return quickSelect(a, l, j, k);    // 答案在左半边
    if (k >= i) return quickSelect(a, i, r, k);    // 答案在右半边
    return a[k];                                   // j < k < i：夹在中间的都等于 pivot
}
int findKthLargest(vector<int>& nums, int k) {
    int n = nums.size();
    return quickSelect(nums, 0, n - 1, n - k);     // 第 k 大 = 升序后下标 n - k
}
  • 堆排序的第二个循环每次把堆的范围缩小一格：siftDown(a, end, 0) 的第二个参数是当前堆的大小，已经换到末尾的元素不再参与。
  • 215 的两种解法怎么选：快速选择平均 O(n)、最坏 O(n²)，随机选基准让最坏情况不依赖输入；大小为 K 的小顶堆是稳定的 O(n log K)，而且能处理数据流（见 6.1 的 Top K）。面试里先写快速选择，再口头补充堆的做法和各自的适用场景。
  • 快速选择和 6.2 的快排是同一个划分过程，区别只是划分之后只进入包含第 k 个位置的那一半，所以平均代价是 n + n/2 + n/4 + …，收敛到 O(n)。

7.二叉搜索树与平衡树

  • 二叉搜索树：左子树全部小于根，右子树全部大于根，中序遍历有序。问题是输入有序时会退化成链表，O(n)。
  • 平衡树：通过旋转限制树高。旋转只改变父子关系，不改变中序顺序，所以不会破坏有序性。
  • AVL：任意节点左右子树高度差不超过 1，高度不超过约 1.44 log n，最平衡，查找最快。
  • 红黑树：平衡条件更宽松（最长路径不超过最短路径的两倍），高度不超过 2 log(n + 1)，换来的是插入删除时更少的旋转。
  • 各种树的对比表、epoll 为什么用红黑树见 C++ 笔记 5.3；map 和 set 的接口与迭代器规则见 4.4。

面试常考代码

面试不会让手写红黑树，考的是二叉搜索树本身的操作：查找、插入、删除、验证、中序遍历，以及「旋转是怎么回事」。

struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int v) : val(v), left(nullptr), right(nullptr) {}
};
// 700. 查找
TreeNode* searchBST(TreeNode* root, int val) {
    while (root && root->val != val) root = val < root->val ? root->left : root->right;
    return root;
}
// 701. 插入：一路比较走到空位置，新节点一定是叶子
TreeNode* insertIntoBST(TreeNode* root, int val) {
    if (!root) return new TreeNode(val);
    if (val < root->val) root->left = insertIntoBST(root->left, val);
    else root->right = insertIntoBST(root->right, val);
    return root;
}
// 450. 删除
TreeNode* deleteNode(TreeNode* root, int key) {
    if (!root) return nullptr;
    if (key < root->val) root->left = deleteNode(root->left, key);
    else if (key > root->val) root->right = deleteNode(root->right, key);
    else {
        if (!root->left) return root->right;       // 没有左孩子（包括叶子）：右孩子顶上来
        if (!root->right) return root->left;
        TreeNode* succ = root->right;              // 两个孩子都有：找右子树里最小的（后继）
        while (succ->left) succ = succ->left;
        root->val = succ->val;                     // 用后继的值覆盖自己，
        root->right = deleteNode(root->right, succ->val);   // 再去右子树里删掉后继
    }
    return root;
}
// 98. 验证二叉搜索树：每个节点都要落在祖先给出的 (lo, hi) 区间里，只和父节点比是错的
bool isValidBST(TreeNode* root, long long lo = LLONG_MIN, long long hi = LLONG_MAX) {
    if (!root) return true;
    if (root->val <= lo || root->val >= hi) return false;
    return isValidBST(root->left, lo, root->val) && isValidBST(root->right, root->val, hi);
}
// 230. 二叉搜索树中第 K 小的元素：迭代版中序遍历，数到第 k 个就停
int kthSmallest(TreeNode* root, int k) {
    stack<TreeNode*> st;
    while (root || !st.empty()) {
        while (root) { st.push(root); root = root->left; }   // 一路向左压栈
        root = st.top();
        st.pop();
        if (--k == 0) return root->val;
        root = root->right;
    }
    return -1;
}
// 左旋：x 的右孩子 y 上位，x 变成 y 的左孩子，y 原来的左子树过继给 x 当右子树。中序顺序不变
TreeNode* rotateLeft(TreeNode* x) {
    TreeNode* y = x->right;
    x->right = y->left;
    y->left = x;
    return y;                                      // 返回新的子树根，由调用方接回父节点
}
  • 删除是最容易写错的。 三种情况：叶子直接删；只有一个孩子，让孩子顶上来；两个孩子都有，用右子树的最小节点（后继）的值覆盖自己，再去右子树里删掉那个后继。前两种情况可以合并成代码里的两行。
  • 验证 BST 的经典错误是只比较节点和它的左右孩子。反例：根是 5，右孩子是 4 且 4 的左孩子是 3。每个节点都满足「左小右大」，但 3 和 4 出现在了 5 的右子树里。正确做法是把祖先给出的上下界一路传下去；上下界用 long long，因为节点值可以等于 INT_MIN 或 INT_MAX。
  • 旋转只改三个指针，中序顺序不变，所以它能调整树高而不破坏有序性。右旋是完全对称的写法。

Q12 · 红黑树的性质分别保证了什么，为什么 map 选它

5 条追问与解答
  • 五条性质里真正起作用的是哪两条？ 五条是：节点非红即黑；根是黑的；空叶子是黑的；红节点的孩子必须是黑的；从任一节点到它下面所有空叶子的路径上黑节点数相同。起作用的是后两条：黑高相同意味着最短的路径是全黑，不能连续红意味着最长的路径最多是红黑交替，所以最长路径不超过最短路径的两倍，树高不超过 2 log(n + 1)。
  • map 为什么用红黑树而不是 AVL？ AVL 更平衡，查找略快，但为了维持严格的平衡，删除时最坏要沿路径旋转 O(log n) 次。红黑树插入最多旋转 2 次、删除最多 3 次，其余的修复都是变色，而变色不改变树的结构，便宜得多。通用容器的读写比例未知，所以选写入代价更稳定的红黑树；明确读远多于写的场景可以选 AVL。
  • 新插入的节点为什么染成红色？ 染黑一定会让经过它的路径比别的路径多一个黑节点，破坏「黑高相同」，而这是一条全局性质，修复要牵动整棵树。染红最多破坏「不能连续红」（父节点恰好也是红的），这是局部问题，通过变色和至多两次旋转向上修复就行。选代价小的那种违规。
  • 已经有哈希表了，为什么还需要平衡树？ 哈希函数把 key 打散，key 之间的大小关系就丢了。需要范围查询、找前驱后继、按序遍历、取第 k 小的时候只能用有序结构。另外平衡树的 O(log n) 是最坏保证，哈希表的 O(1) 只是平均。
  • 怎么在平衡树上查第 k 小、查某个值的排名？ 每个节点多存一个子树大小。查第 k 小时，拿 k 和左子树大小比较，决定往左走、命中当前节点、还是往右走（同时 k 减去左子树大小加一）。旋转只影响两个节点的子树大小，O(1) 就能重新算好。std::set 没有暴露这个能力，面试里通常用树状数组加离散化，或者对顶堆来替代。

8.B 树、B+ 树与 LSM 树

面向磁盘的结构，设计目标从「减少比较次数」变成「减少 IO 次数」。一个节点就是一个磁盘页（InnoDB 是 16KB），里面打包几百到上千个 key，整棵树只有三四层。

面试常考代码

B+ 树面试里一般只到「画出结构、讲清查找和范围查询的过程」，偶尔会让写节点定义和查找，不会让手写插入分裂。下面是这个范围内的最小实现。

// B+ 树的节点结构、单点查找、范围查询。面试一般只要求到这个程度，不会让手写插入和分裂
struct BPlusNode {
    bool isLeaf;
    vector<int> keys;                              // 节点内有序
    vector<BPlusNode*> children;                   // 内部节点用：children.size() == keys.size() + 1
    vector<int> values;                            // 叶子节点用：和 keys 一一对应
    BPlusNode* next = nullptr;                     // 叶子节点用：指向右边相邻的叶子
};
// 从根走到 key 应该在的那个叶子。约定：keys[i] 是 children[i + 1] 这棵子树里的最小 key
BPlusNode* findLeaf(BPlusNode* root, int key) {
    BPlusNode* cur = root;
    while (!cur->isLeaf) {
        int i = upper_bound(cur->keys.begin(), cur->keys.end(), key) - cur->keys.begin();   // 节点内二分
        cur = cur->children[i];                    // 有几个 key 不大于它，就走第几个孩子
    }
    return cur;
}

bool bplusSearch(BPlusNode* root, int key, int& value) {
    BPlusNode* leaf = findLeaf(root, key);
    int i = lower_bound(leaf->keys.begin(), leaf->keys.end(), key) - leaf->keys.begin();
    if (i == (int)leaf->keys.size() || leaf->keys[i] != key) return false;
    value = leaf->values[i];
    return true;
}
// 范围查询 [lo, hi]：先定位到 lo 所在的叶子，然后顺着叶子链表往右扫，不用再回到上层
vector<int> bplusRange(BPlusNode* root, int lo, int hi) {
    vector<int> res;
    for (BPlusNode* leaf = findLeaf(root, lo); leaf; leaf = leaf->next) {
        for (int i = 0; i < (int)leaf->keys.size(); ++i) {
            if (leaf->keys[i] > hi) return res;
            if (leaf->keys[i] >= lo) res.push_back(leaf->values[i]);
        }
    }
    return res;
}
  • 单点查找的每一层都是「节点内二分 + 走向一个孩子」。 真实数据库里一个节点就是一个磁盘页，这一步对应一次 IO，所以查找的 IO 次数等于树高。
  • 范围查询只在开头走一次树，之后全靠叶子上的 next 指针。这就是 B+ 树相对 B 树在范围扫描上的优势在代码里的体现。

Q13 · 数据库索引为什么用 B+ 树

5 条追问与解答
  • 为什么不用红黑树？ 红黑树每个节点只有一个 key，一千万行数据的树高是二十多层，每层一次随机 IO，一次查询就是二十多次磁盘访问。B+ 树每个节点塞满一页，扇出上千，同样的数据只要三层。在内存里比较次数是瓶颈，在磁盘上 IO 次数才是，所以要用「矮而胖」的树。
  • B 树和 B+ 树差在哪？ B 树的内部节点也存数据，B+ 树的数据全在叶子、内部节点只存 key。后者带来三个好处：内部节点不放数据，同一页能放下更多 key，扇出更大、树更矮；所有查询都走到叶子，路径长度一致，性能稳定；叶子之间用链表串起来，范围查询定位到起点后顺着链表扫就行，是顺序 IO，B 树则要在树上来回做中序遍历。
  • 「单表两千万行」这个经验值是怎么算出来的？ 一页 16KB，主键 bigint 8 字节加页指针 6 字节约 14 字节，内部节点的扇出约 1170。假设一行 1KB，一个叶子页放 16 行。三层树能放 1170 × 1170 × 16，约 2190 万行。超过这个量级树会长到第四层，每次查询多一次 IO。所以这个数字取决于行的大小，行越小能放得越多，它不是一个固定的上限。
  • Redis 用跳表，为什么数据库不用？ 跳表的每一步都是一次指针跳转，放到磁盘上就是一次随机 IO，而它的层数是 log₂ n，二十多层。B+ 树一次 IO 读进来一整页，上千个 key 在内存里二分，一次 IO 就排除掉了 99.9% 的范围。内存里指针跳转很便宜，所以 Redis 可以用跳表；磁盘上不行。结构的选择是由存储介质的代价模型决定的。
  • LSM 树为什么写得快，代价是什么？ 写入只做两件事：追加写日志，插入内存里的有序结构（通常是跳表）。内存表满了就整体刷成一个不可变的有序文件。全程都是顺序 IO，没有 B+ 树那种原地更新随机页和页分裂。代价在读和后台：读要从新到旧查多层文件，靠每个文件配一个布隆过滤器来跳过不含这个 key 的文件；后台要不断合并文件，带来写放大。写多读少的场景（日志、时序、KV 存储）用它，LevelDB、RocksDB、HBase 都是这个结构。

9.Trie 与字符串结构

基础实现见本节后面的代码，这里先补三个常见的延伸方向：

  • 0-1 Trie：把整数按二进制从高位到低位插入 Trie。求「数组中两个数的最大异或值」时，对每个数从高位往下走，每一位都优先走和自己相反的那个孩子。原因是异或结果的高位是 1 比低位全是 1 还大，所以可以逐位贪心，O(32n)。
  • 最长前缀匹配：路由表查找的就是「和目标地址匹配的最长前缀」。在 Trie 上一路往下走，记录沿途最后一个带结束标记的节点就是答案。
  • AC 自动机：Trie 加失配指针，一次扫描文本同时匹配多个模式串（敏感词过滤）。失配指针的含义和 KMP 的 next 数组一致：当前路径的最长真后缀同时也是某个模式串前缀的那个位置。1032 题的标准解法就是它。

class Trie {
    struct Node {
        Node* next[26] = {};                       // 全部初始化为 nullptr
        bool isEnd = false;
    };
    Node* root_ = new Node();

    Node* walk(const string& s) {                  // 沿着 s 往下走，走不通返回 nullptr
        Node* cur = root_;
        for (char c : s) {
            cur = cur->next[c - 'a'];
            if (!cur) return nullptr;
        }
        return cur;
    }
public:
    void insert(string word) {
        Node* cur = root_;
        for (char c : word) {
            if (!cur->next[c - 'a']) cur->next[c - 'a'] = new Node();
            cur = cur->next[c - 'a'];
        }
        cur->isEnd = true;
    }
    bool search(string word) { Node* n = walk(word); return n && n->isEnd; }
    bool startsWith(string prefix) { return walk(prefix) != nullptr; }
};
// 421. 数组中两个数的最大异或值：0-1 Trie，每一位都优先走和自己相反的那一边
struct BitNode {
    BitNode* next[2] = {};
};

int findMaximumXOR(vector<int>& nums) {
    BitNode* root = new BitNode();
    int best = 0;
    for (int x : nums) {
        BitNode* cur = root;                       // 第一步：把 x 从高位到低位插进 Trie
        for (int b = 30; b >= 0; --b) {
            int bit = (x >> b) & 1;
            if (!cur->next[bit]) cur->next[bit] = new BitNode();
            cur = cur->next[bit];
        }
        cur = root;                                // 第二步：拿 x 去和已经插入的数配对
        int val = 0;
        for (int b = 30; b >= 0; --b) {
            int bit = (x >> b) & 1;
            if (cur->next[bit ^ 1]) {              // 有相反的位可走：这一位的异或结果是 1
                val |= 1 << b;
                cur = cur->next[bit ^ 1];
            } else {
                cur = cur->next[bit];
            }
        }
        best = max(best, val);
    }
    return best;
}
  • 常见变形：带通配符的搜索（211，遇到 . 就枚举所有孩子做 DFS）、带计数的删除（1804，每个节点多存一个经过次数）、自动补全（642，节点上缓存热度最高的几条）。
  • 421 为什么从第 30 位开始？ 题目保证数值非负且小于 2^31，最高的有效位是第 30 位。从高位到低位贪心是因为高位的 1 比所有低位的 1 加起来还大，高位能取到 1 就一定要取。

class UnionFind {
    vector<int> parent_, size_;
public:
    int count;                                     // 当前还有多少个集合
    UnionFind(int n) : parent_(n), size_(n, 1), count(n) {
        for (int i = 0; i < n; ++i) parent_[i] = i;
    }
    int find(int x) {
        if (parent_[x] != x) parent_[x] = find(parent_[x]);   // 路径压缩：沿途节点直接挂到根上
        return parent_[x];
    }
    bool unite(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;                // 本来就在一个集合里
        if (size_[ra] < size_[rb]) swap(ra, rb);   // 按大小合并：小树挂到大树下面
        parent_[rb] = ra;
        size_[ra] += size_[rb];
        --count;
        return true;
    }
};
// 547. 省份数量
int findCircleNum(vector<vector<int>>& isConnected) {
    int n = isConnected.size();
    UnionFind uf(n);
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            if (isConnected[i][j]) uf.unite(i, j);
        }
    }
    return uf.count;
}

Q14 · 并查集的两个优化各自解决什么问题

4 条追问与解答
  • 路径压缩和按秩合并分别在做什么？ 路径压缩是在 find 的过程中把沿途的节点全部直接挂到根下面，让之后的查找一步到位。按秩（或按大小）合并是合并时把矮的树挂到高的树下面，从源头上不让树长高。只用其中一个是 O(log n)，两个一起用是摊还 O(α(n))。α 是反阿克曼函数，对宇宙中原子数量级的 n 也不超过 5，可以当常数。
  • 并查集为什么不支持删除和拆分？ 因为合并是有损的。union 之后只留下了「现在的根是谁」，丢掉了「当初是哪两棵树合并成的」；路径压缩又进一步抹掉了树原本的形状，没有信息可以用来还原。需要删边的连通性问题有两种绕法：离线倒着处理，把删边变成加边（803 打砖块）；或者用可撤销并查集，只做按秩合并、不做路径压缩，用栈记录每次修改以便回滚。
  • 带权并查集能解决什么问题？ 每个节点额外记录它和父节点之间的关系值（差值、比值、奇偶性），路径压缩时沿路累加或累乘。适用于关系可以传递的问题：399 除法求值（a / b 和 b / c 已知，求 a / c）、判断二分图和敌对关系。两个元素在同一个集合里，就说明它们之间的关系可以通过各自到根的关系推算出来。
  • 求连通分量，并查集和 DFS 怎么选？ 图是静态的、只求一次，DFS 是 O(V + E)，代码更简单。边不断增加、查询穿插其间的在线场景，并查集每次操作接近 O(1)，而 DFS 每次都得重跑。Kruskal 算法正是这种场景：按权重从小到大加边，每加一条之前要问两端是否已经连通。

void sink(vector<vector<char>>& grid, int r, int c) {
    if (r < 0 || r >= (int)grid.size() || c < 0 || c >= (int)grid[0].size()) return;
    if (grid[r][c] != '1') return;
    grid[r][c] = '0';                              // 原地标记已访问
    sink(grid, r + 1, c);
    sink(grid, r - 1, c);
    sink(grid, r, c + 1);
    sink(grid, r, c - 1);
}

        }
    }

}
// 207. 课程表：邻接表建图 + 拓扑排序（Kahn）。能全部出队就说明没有环
bool canFinish(int numCourses, vector<vector<int>>& prerequisites) {
    vector<vector<int>> adj(numCourses);
    vector<int> indeg(numCourses, 0);
    for (auto& p : prerequisites) {                // p = {a, b}：先学 b 才能学 a，边 b -> a
        adj[p[1]].push_back(p[0]);
        ++indeg[p[0]];
    }
    queue<int> q;
    for (int i = 0; i < numCourses; ++i) if (indeg[i] == 0) q.push(i);
    int done = 0;
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        ++done;
        for (int v : adj[u]) if (--indeg[v] == 0) q.push(v);
    }
    return done == numCourses;
}
// 743. 网络延迟时间：Dijkstra + 小顶堆。节点编号从 1 开始
int networkDelayTime(vector<vector<int>>& times, int n, int k) {
    vector<vector<pair<int, int>>> adj(n + 1);     // adj[u] = {{v, w}, ...}
    for (auto& t : times) adj[t[0]].push_back({t[1], t[2]});
    vector<int> dist(n + 1, INT_MAX);
    priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> pq;   // {距离, 节点}
    dist[k] = 0;
    pq.push({0, k});
    while (!pq.empty()) {
        auto [d, u] = pq.top();
        pq.pop();
        if (d > dist[u]) continue;                 // 过期的堆项（懒删除）
        for (auto [v, w] : adj[u]) {
            if (d + w < dist[v]) {
                dist[v] = d + w;
                pq.push({dist[v], v});
            }
        }
    }
    int res = 0;
    for (int i = 1; i <= n; ++i) {
        if (dist[i] == INT_MAX) return -1;         // 有节点到不了
        res = max(res, dist[i]);
    }
    return res;
}

  • Dijkstra 里那句 if (d > dist[u]) continue 不能省。 同一个节点可能因为多次松弛而多次入堆，先出堆的是最短的那次，后面出来的都是过期项；不跳过的话结果仍然正确，但会做大量无用的松弛，复杂度失去保证。

Q15 · 图的存储方式怎么选

3 条追问与解答
  • CSR 是什么，为什么大规模图计算都用它？ 两个数组：offsets 长度为 V + 1，edges 长度为 E，节点 u 的邻居就是 edges[offsets[u]] 到 edges[offsets[u + 1]] 之前的这一段。整张图只有两块连续内存，遍历邻居时是纯顺序访存，也没有任何逐节点的内存分配。GPU 上稀疏矩阵的标准格式也是它，稀疏矩阵和图的邻接结构本来就是同一个东西。代价是加边要整体重建，只适合静态图。
  • vector<vector<int>> 的邻接表有什么问题？ 每个内层 vector 都是一次独立的堆分配，V 很大时分配次数多，各个节点的邻居表散落在堆的各处。面试题的规模下没有影响，这是默认写法。规模大时换成 CSR，或者用三个数组模拟链表的「链式前向星」，把所有的边放进一块连续内存。
  • 网格类题目需要先建图吗？ 不需要，它是隐式图：节点就是坐标 (r, c)，邻居由方向数组现场算出来，访问标记用同样大小的二维数组，或者在允许的情况下直接改原数组。显式建图只会多一倍内存和一遍预处理，没有任何收益。

// 560. 和为 K 的子数组：前缀和 + 哈希。子数组和 = 两个前缀和之差
int subarraySum(vector<int>& nums, int k) {
    unordered_map<int, int> cnt;                   // 前缀和 -> 出现次数
    cnt[0] = 1;                                    // 空前缀：让「从下标 0 开始的子数组」也能被数到
    int sum = 0, res = 0;
    for (int x : nums) {
        sum += x;
        if (cnt.count(sum - k)) res += cnt[sum - k];
        ++cnt[sum];                                // 先查后存，避免把空子数组算进去
    }
    return res;
}

// 56. 合并区间：按左端点排序后，新区间只可能和结果里的最后一个重叠
vector<vector<int>> mergeIntervals(vector<vector<int>>& intervals) {
    sort(intervals.begin(), intervals.end());
    vector<vector<int>> res;
    for (auto& cur : intervals) {
        if (!res.empty() && cur[0] <= res.back()[1]) res.back()[1] = max(res.back()[1], cur[1]);
        else res.push_back(cur);
    }
    return res;
}

树状数组（307）：单点修改 + 前缀查询，两个循环方向相反：tree_[i] 管辖以 i 结尾、长度为 i & -i 的一段，查询时不断减去这个长度往前拼，更新时不断加上它去找所有覆盖 i 的节点。

class NumArray {
    vector<int> nums_, tree_;                      // tree_ 下标从 1 开始，tree_[i] 管辖长度为 lowbit(i) 的一段
    int n_;
    void add(int i, int delta) {
        for (; i <= n_; i += i & -i) tree_[i] += delta;
    }
    int prefix(int i) {
        int s = 0;
        for (; i > 0; i -= i & -i) s += tree_[i];
        return s;
    }
public:
    NumArray(vector<int>& nums) : nums_(nums), tree_(nums.size() + 1, 0), n_(nums.size()) {
        for (int i = 0; i < n_; ++i) add(i + 1, nums[i]);
    }
    void update(int index, int val) {
        add(index + 1, val - nums_[index]);        // 树里存的是和，所以传增量而不是新值
        nums_[index] = val;
    }
    int sumRange(int left, int right) { return prefix(right + 1) - prefix(left); }
};

线段树（307 的另一种解法）：同样是单点修改 + 区间求和。把 sum_ 和汇总时的加法换成 max，就是区间最值。

// 线段树（307. 区域和检索 - 数组可修改）：单点修改 + 区间求和。节点编号从 1 开始，左右孩子是 2k 和 2k + 1
class SegTree {
    int n_;
    vector<int> sum_;

    void build(vector<int>& a, int node, int l, int r) {
        if (l == r) { sum_[node] = a[l]; return; }
        int mid = (l + r) / 2;
        build(a, 2 * node, l, mid);
        build(a, 2 * node + 1, mid + 1, r);
        sum_[node] = sum_[2 * node] + sum_[2 * node + 1];
    }
    void update(int node, int l, int r, int idx, int val) {
        if (l == r) { sum_[node] = val; return; }
        int mid = (l + r) / 2;
        if (idx <= mid) update(2 * node, l, mid, idx, val);
        else update(2 * node + 1, mid + 1, r, idx, val);
        sum_[node] = sum_[2 * node] + sum_[2 * node + 1];     // 回溯时重新汇总
    }
    int query(int node, int l, int r, int ql, int qr) {
        if (ql <= l && r <= qr) return sum_[node];             // 当前节点被查询区间完全覆盖
        int mid = (l + r) / 2, s = 0;
        if (ql <= mid) s += query(2 * node, l, mid, ql, qr);
        if (qr > mid) s += query(2 * node + 1, mid + 1, r, ql, qr);
        return s;
    }
public:
    SegTree(vector<int>& a) : n_(a.size()), sum_(4 * a.size()) { build(a, 1, 0, n_ - 1); }
    void update(int idx, int val) { update(1, 0, n_ - 1, idx, val); }
    int sumRange(int l, int r) { return query(1, 0, n_ - 1, l, r); }
};

  • 线段树和树状数组选哪个写？ 题目只要求「单点修改 + 区间和」就写树状数组，代码短一半。要区间最值、或者要区间修改，才写线段树。

Q16 · 线段树的懒标记为什么能把区间修改降到 O(log n)

4 条追问与解答
  • 懒标记做了什么？ 任何一个区间最多被拆成 2 log n 个「被完整覆盖的节点」。区间修改时只走到这些节点就停下：更新节点自己的聚合值，再记一笔「我欠我的子树一次修改」，不继续往下。等到以后有操作需要进入这个节点的子树时，才把这笔欠账下推一层。查询时沿途下推，保证读到的每个节点都是最新的。没有人访问的子树永远不会被真正更新，省掉的就是这部分工作。
  • 什么样的运算能放到线段树上？ 聚合运算要满足结合律（和、最值、最大公约数、矩阵乘法），这样父节点的值才能由两个孩子合并出来。要支持懒标记还需要两个条件：标记之间可以叠加（先加 3 再加 5 等于加 8），以及标记对聚合值的影响能 O(1) 算出来。「区间加」对「区间和」的影响是增量乘以区间长度，可以；「区间加」对「区间内不同元素的个数」的影响算不出来，就不行。
  • 数组为什么要开 4n？ 用数组存线段树时，节点 i 的孩子编号是 2i 和 2i + 1，这是按满二叉树来编号的。n 不是 2 的幂时最后一层并不满，但编号仍然按满的来占位，最大编号可以接近 4n。开 2n 在 n 恰好是 2 的幂时够用，其他情况会越界。
  • 值域到 10^9、又必须在线回答（比如 732 我的日程安排表 III），怎么办？ 动态开点：不预先建树，节点只在第一次被访问到时创建，每次操作最多新建 O(log V) 个节点，总空间 O(q log V)。如果所有操作事先已知（离线），可以先把出现过的坐标离散化到 [0, 2q) 再建普通线段树。题目要求在线的话，就只能动态开点。

13.位图、布隆过滤器与概率结构

用精度换空间。「海量数据」类的面试题基本都落在这一节。

  • 位图：用 1 个 bit 表示一个整数在不在。全部 32 位无符号整数一共 2^32 个 bit，也就是 512MB，和元素个数无关。
  • 布隆过滤器：m 个 bit 加 k 个哈希函数。插入时把 k 个位置置 1；查询时 k 个位置全是 1 回答「可能存在」，有任何一个是 0 回答「一定不存在」。误判率约为 (1 - e(-kn/m))k，k 取 (m/n) · ln 2 时最优。每个元素分配 10 个 bit、k 取 7，误判率约 1%。
  • HyperLogLog：估计去重后的元素个数。依据是哈希值里前导零的最大长度 ρ 暗示着大约见过 2^ρ 个不同的值；分成 16384 个桶各自估计，再取调和平均来压低方差。Redis 的实现固定占 12KB，标准误差 0.81%。
  • Count-Min Sketch：估计每个元素出现的次数。d 行 w 列的计数器，每行用一个哈希函数，插入时 d 个位置各加一，查询取 d 个位置里的最小值。因为冲突只会让计数变大，所以结果只会高估、不会低估，取最小值就是取受冲突影响最小的那个。用在热点 key 检测和近似 LFU（Caffeine 的 TinyLFU）上。

位图和布隆过滤器。面试里多数时候只要求讲原理，但这两个实现都很短，写出来是加分项。

// 位图：1 个 bit 表示一个整数在不在
class Bitmap {
    vector<unsigned> bits_;                        // 每个 unsigned 管 32 个数
public:
    Bitmap(int n) : bits_((n + 31) / 32, 0) {}
    void set(int x) { bits_[x / 32] |= 1u << (x % 32); }
    void clear(int x) { bits_[x / 32] &= ~(1u << (x % 32)); }
    bool test(int x) { return (bits_[x / 32] >> (x % 32)) & 1; }
};
// 布隆过滤器：m 个 bit + k 个哈希函数。说「不存在」一定对，说「存在」可能错
class BloomFilter {
    vector<bool> bits_;
    int m_, k_;

    int pos(const string& s, int i) {              // 第 i 个哈希函数：用两个基础哈希组合出 k 个
        size_t h1 = hash<string>()(s);
        size_t h2 = hash<string>()(s + "#");
        return (h1 + i * h2) % m_;
    }
public:
    BloomFilter(int m, int k) : bits_(m, false), m_(m), k_(k) {}
    void add(const string& s) {
        for (int i = 0; i < k_; ++i) bits_[pos(s, i)] = true;
    }
    bool mayContain(const string& s) {
        for (int i = 0; i < k_; ++i) {
            if (!bits_[pos(s, i)]) return false;   // 有一位是 0：一定没加过
        }
        return true;                               // 全是 1：可能加过，也可能是别的元素凑出来的
    }
};
  • 位图的三个操作都是「先定位到第几个 unsigned，再定位到其中第几位」：x / 32 和 x % 32。置位用或，清位用「与上取反」，查询用右移后与 1。
  • 布隆过滤器里的 k 个哈希函数不需要真的找 k 个：用两个基础哈希值 h1、h2 线性组合出 h1 + i × h2 就够了，这是工程上的标准做法。
  • 没有 remove 是故意的，原因见下面的 Q。

Q17 · 布隆过滤器为什么只有假阳性、没有假阴性

4 条追问与解答
  • 原因是什么？ 插入时置为 1 的位永远不会被清零，所以插入过的元素再来查询时，它的 k 个位置必然全是 1，不可能被判成不存在。而一个从没插入过的元素，它的 k 个位置有可能恰好被别的元素凑齐，于是被误判为存在。
  • 典型的用途有什么共同点？ 缓存穿透防护（先问过滤器，不存在的 key 直接拒绝，不去查数据库）、LSM 树读路径（每个文件配一个，跳过不可能含有这个 key 的文件）、爬虫的 URL 去重。共同点是：否定的回答很有价值而且必须可靠，肯定的回答反正还要去做一次真正的查询，错了只是多花一次查询的代价。
  • 为什么不能删除，要删除怎么办？ 一个 bit 可能被多个元素共用，删除时把它清零会连带着「删掉」别的元素，制造出假阴性。计数布隆过滤器把每个 bit 换成一个 4 位的计数器，插入加一、删除减一，空间变成四倍。Cuckoo filter 存的是指纹，天然支持删除，空间效率也更高。
  • 十亿个 URL 去重，需要多少内存？ 用哈希集合：一个 URL 平均几十字节，再加上节点和指针的开销，总量在百 GB 级别，单机放不下。用布隆过滤器并接受 1% 的误判：10 bit × 10 亿，约 1.2GB。如果要求精确，就按 hash(url) % 1000 把数据分到 1000 个小文件里，相同的 URL 必然落进同一个文件，再逐个文件用哈希集合去重。

面试常考代码

并发方向最常让手写的数据结构是有界阻塞队列，也就是生产者-消费者模型。线程池、单例、手写互斥锁见 C++ 笔记 8.5 和 8.6。

// 有界阻塞队列（生产者-消费者）：一把锁 + 两个条件变量
class BlockingQueue {
    queue<int> q_;
    int cap_;
    mutex mtx_;
    condition_variable notFull_, notEmpty_;
public:
    BlockingQueue(int cap) : cap_(cap) {}
    void push(int x) {
        unique_lock<mutex> lk(mtx_);
        notFull_.wait(lk, [&] { return (int)q_.size() < cap_; });   // 满了就等；带条件的 wait 自动处理虚假唤醒
        q_.push(x);
        notEmpty_.notify_one();
    }
    int pop() {
        unique_lock<mutex> lk(mtx_);
        notEmpty_.wait(lk, [&] { return !q_.empty(); });            // 空了就等
        int x = q_.front();
        q_.pop();
        notFull_.notify_one();
        return x;
    }
};
  • wait 必须带条件（或者写在 while 循环里）。 条件变量存在虚假唤醒，被唤醒不代表条件真的成立；而且多个消费者同时被唤醒时，只有一个能抢到元素，其余的必须重新检查再继续等。
  • 为什么用两个条件变量？ 只用一个的话，notify_one 可能把一个生产者唤醒去通知另一个生产者「队列不满了」，而真正在等的消费者没被叫醒，严重时所有线程都在等。分成「不满」和「不空」两个，通知才能送到对的人手里。
  • 必须用 unique_lock 而不是 lock_guard，因为 wait 在睡眠期间要把锁释放掉、醒来再重新加锁，lock_guard 不支持中途解锁。

Q18 · 把一个哈希表改成线程安全，有哪几档做法

4 条追问与解答
  • 从粗到细有哪几档？ 一把全局锁 → 分片，每片一把锁，按 hash % N 选片（Java 7 的 ConcurrentHashMap 是 16 个段）→ 桶级别：空桶用 CAS 插入，非空桶锁住桶的头节点（Java 8）→ 读多写少时用读写锁，或者写时复制。粒度越细并发度越高，但 size()、扩容、遍历这类需要全局视图的操作就越难做：分片之后 size() 要么逐片加锁求和，要么每片维护一个原子计数、接受结果是近似的。
  • LRU 缓存能用读写锁优化吗？ 基本不能。LRU 的 get 要把节点挪到链表头部，读操作同时也是对链表的写操作，读写锁的读锁根本用不上。常规做法是分片，每片是一个独立的 LRU 加一把互斥锁，代价是淘汰顺序从全局 LRU 变成了分片内 LRU。更进一步的做法（Caffeine）是 get 只把「访问了谁」记进一个无锁的环形缓冲区，攒够一批之后再由单个线程统一应用到链表上，让读路径完全不碰锁。
  • 无锁结构真正难的为什么是内存回收，而不是 CAS？ 线程 A 读到了一个节点的指针，随即被调度出去；线程 B 把这个节点从结构里摘下来并释放了内存；A 醒来之后解引用，访问的是已经释放的内存。带垃圾回收的语言没有这个问题，因为只要 A 还持有引用，节点就不会被回收。C++ 需要 hazard pointer（每个线程公示自己正在使用的指针，回收之前先检查有没有人在用）或者基于 epoch 的回收（等所有线程都离开了旧的 epoch 才真正释放）。
  • ABA 问题是什么？ CAS 只比较值���否相等。线程 A 读到指针值 P，期间 P 指向的节点被释放，分配器恰好把同一个地址又分给了一个新节点，A 的 CAS 比较发现仍然是 P，于是成功了，但节点早已不是原来那个，链表就此损坏。它的根源和上一条相同，都是地址被复用。解法是给指针配一个版本号一起做 CAS（x86-64 上可以借用指针的高 16 位），或者靠上面两种回收机制保证地址在还有人使用期间不会被复用。
